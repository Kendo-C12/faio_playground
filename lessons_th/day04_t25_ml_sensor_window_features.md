**Window หรือ segment (หน้าต่างข้อมูล หรือ ช่วงข้อมูล)** คือ กลุ่มของแถวข้อมูลที่อยู่ติดกันตามเวลา ซึ่งถูกนับรวมเป็นตัวอย่างเดียว

ข้อมูลจากเซ็นเซอร์มาถึงเราทีละแถว หนึ่งแถวคือการวัดหนึ่งครั้ง เช่น `ax, ay, az, ...` แต่คำตอบที่ต้องทำนายนั้นอธิบาย *ช่วงเวลาหนึ่งช่วง* เช่น "การทำท่าโยคะครั้งนี้ถูกต้อง" หน่วยที่คำตอบผูกอยู่ด้วยจึงคือหน้าต่างข้อมูล ไม่ใช่แถว และหัวข้อนี้คือเรื่องของการยุบหน้าต่างที่มีหลายร้อยแถว ให้เหลือข้อมูลเพียงแถวเดียว

หัวข้อนี้สำคัญเพราะโจทย์ task 5 เก็บข้อมูลที่ 200 ครั้งต่อวินาที การทำท่าหนึ่งครั้งจึงมีข้อมูลหลายร้อยแถว ถ้ายัดข้อมูลดิบทีละแถวเข้าโมเดลตรง ๆ ผลที่ได้จะไม่มีความหมายเลย

## [concept-first] ทฤษฎีก่อน แล้วดูตัวอย่าง

### ทำไมข้อมูลดิบทีละแถวใช้กับโมเดลแบบตารางไม่ได้

มีเหตุผลสามข้อที่เป็นอิสระจากกัน และแต่ละข้อเพียงข้อเดียวก็ทำให้ใช้ไม่ได้แล้ว

- **เรื่องรูปร่างของข้อมูล** คำตอบมีอยู่หนึ่งค่าต่อการทำท่าหนึ่งครั้ง ถ้าแตกออกเป็น 400 แถว ทุกแถวจะได้สำเนาของคำตอบเดียวกันไป กลายเป็นการสอนโมเดลให้ตอบคำถามว่า "ช่วงเวลา 5 มิลลิวินาทีนี้ถูกต้องหรือไม่" ซึ่งเป็นคำถามที่ไม่มีช่วงเวลาสั้น ๆ ช่วงไหนตอบได้

- **เรื่องการมองไม่เห็นบริบท** โมเดลที่ดูข้อมูลทีละแถวเห็นเพียงตัวเลขหกตัว โดยไม่รู้เลยว่าแถวก่อนหน้าและแถวถัดไปเป็นอย่างไร ผลคือความราบรื่นของการเคลื่อนไหว จังหวะเวลา และการที่แกนต่าง ๆ ขยับ *พร้อมกัน* ซึ่งเป็นทุกอย่างที่แยกท่าที่ถูกออกจากท่าที่ผิด กลายเป็นสิ่งที่มองไม่เห็น

- **เรื่องการรวมคำตอบ** สุดท้ายจะได้คำทำนาย 400 ค่าต่อการทำท่าหนึ่งครั้ง และไม่มีวิธีที่มีหลักการรองรับว่าจะรวม 400 ค่านั้นกลับมาเป็นคำตอบเดียวได้อย่างไร

ข้อสรุปคือ สรุปข้อมูลก่อน แล้วค่อยแบ่งประเภท และผลลัพธ์ต้องเป็นหนึ่งแถวต่อหนึ่ง `id`

### เลขคณิตของอัตราการสุ่มตัวอย่าง

**Sampling rate (อัตราการสุ่มตัวอย่าง)** คือ จำนวนครั้งที่เครื่องวัดค่าได้ในหนึ่งวินาที เขียนแทนด้วย $f_s$ และมีหน่วยเป็น Hz ค่า $f_s$ Hz หมายความว่ามี $f_s$ แถวต่อวินาที ดังนั้น

$$
n_{\text{rows}} = \text{duration} \times f_s
\qquad
\text{duration} = \frac{n_{\text{rows}}}{f_s}
$$

เมื่อ $n_{\text{rows}}$ คือ จำนวนแถว และ $\text{duration}$ คือ ระยะเวลาเป็นวินาที

ที่ **200 Hz** ของโจทย์ task 5 หนึ่งวินาทีคือ 200 แถว การทำท่าหนึ่งครั้งที่ใช้เวลา 2 วินาทีคือประมาณ 400 แถว และแถวที่อยู่ติดกันห่างกัน 5 มิลลิวินาที ให้คำนวณตัวเลขนี้กับข้อมูลจริงก่อนจะเชื่อสิ่งที่โจทย์เขียน เพราะค่า $n_{\text{rows}} / 200$ ต้องออกมาอยู่ในช่วงที่สมเหตุสมผลกับการทำท่าโยคะหนึ่งครั้ง คือประมาณ 1 ถึง 10 วินาที

### ชุดคุณลักษณะมาตรฐาน คำนวณหนึ่งชุดต่อหนึ่งหน้าต่างต่อหนึ่งแกน

| คุณลักษณะ | สูตร | สิ่งที่มันจับได้ |
|---|---|---|
| mean (ค่าเฉลี่ย) | $\bar{x}$ | ระดับขณะอยู่นิ่ง หรือทิศทางการวางตัว |
| std, range, RMS (ส่วนเบี่ยงเบน พิสัย ค่ารากที่สองของกำลังสองเฉลี่ย) | $\sqrt{\sum_i (x_i - \bar{x})^2 / n}$, $\max - \min$, $\sqrt{\sum_i x_i^2 / n}$ | ขยับมากแค่ไหน และมีกิจกรรมรวมเท่าไร |
| zero-crossing rate (อัตราการข้ามศูนย์) | สัดส่วนของ $i$ ที่ $\operatorname{sign}(x_i) \ne \operatorname{sign}(x_{i+1})$ | ความถี่ของการแกว่ง เป็นตัวแทนราคาถูกของความถี่ |
| cross-axis correlation (สหสัมพันธ์ระหว่างแกน) | $\operatorname{corr}(a_x, a_y)$ และคู่อื่น ๆ | ขยับอย่างประสานกัน หรือขยับมั่ว |
| magnitude (ขนาดรวม) | $\sqrt{a_x^2 + a_y^2 + a_z^2}$ แล้วคำนวณสถิติของค่านี้ต่อ | กิจกรรมที่ไม่ขึ้นกับทิศการติดเซ็นเซอร์ |
| n_rows (จำนวนแถว) | การนับ | ระยะเวลา |

เมื่อ $x_i$ คือ ค่าที่วัดได้ในแถวที่ $i$ ของหน้าต่างนั้น, $\bar{x}$ คือ ค่าเฉลี่ยของทั้งหน้าต่าง และ $n$ คือ จำนวนแถวในหน้าต่าง

อธิบายแต่ละตัวด้วยคำง่าย ๆ ค่า `mean` บอกว่าท่าโดยรวมเป็นอย่างไร ส่วน `std`, `range` และ `RMS` บอกว่าทำท่านั้นด้วยการเคลื่อนไหวมากน้อยแค่ไหน ค่า zero-crossing rate ทำหน้าที่แทนคุณลักษณะเชิงความถี่ในบท T26 แบบราคาถูก และ cross-axis correlation เป็นรายการเดียวในตารางที่มองเห็นการประสานกันระหว่างแกนได้ ควรคำนวณชุดคุณลักษณะทั้งหมดนี้กับช่องสัญญาณขนาดรวมด้วย เพราะค่าขนาดรวมไม่เปลี่ยนตามวิธีติดเซ็นเซอร์บนร่างกาย

### กฎเรื่องการแบ่งข้อมูลแบบจัดกลุ่ม

หน้าต่างหนึ่งหน้าต่างต้องไม่คร่อมระหว่างฝั่งสอนโมเดลกับฝั่งวัดผลเด็ดขาด ถ้าสุ่มแบ่งทีละแถว แถวจากการทำท่า *ครั้งเดียวกัน* จะไปอยู่ทั้งสองฝั่ง โมเดลจะจำการทำท่าครั้งนั้นได้ และคะแนนที่วัดได้จะกลายเป็นความหวังลม ๆ แล้ง ๆ ที่ไม่มีความหมาย

การสรุปข้อมูลให้เหลือหนึ่งแถวต่อหนึ่ง `id` ก่อน ทำให้การแบ่งข้อมูลธรรมดากลายเป็นการแบ่งแบบจัดกลุ่มโดยอัตโนมัติ นี่คือเหตุผลข้อที่สองที่ควรสรุปข้อมูลก่อน ถ้าจำเป็นต้องแบ่งข้อมูลดิบทีละแถวจริง ๆ ให้ใช้ `GroupShuffleSplit` หรือ `GroupKFold` พร้อมกำหนด `groups=df["id"]` และกฎเดียวกันนี้ใช้กับหน้าต่างที่ซ้อนทับกันด้วย คือ หน้าต่างสองอันที่ใช้แถวร่วมกันต้องอยู่ในส่วนเดียวกัน

## [problem-first] เริ่มจากโจทย์จริง แล้วหาว่าต้องรู้อะไร

เปิดไฟล์ [`task5_Can_You_Become_AI_Yoga_Instructor.md`](../faio-2025/qualification/task5_Can_You_Become_AI_Yoga_Instructor.md) ส่วน Input เขียนว่า "Each repetition is represented by time series of IMU readings sampled at **200 Hz**" แปลว่าการทำท่าหนึ่งครั้งแทนด้วยอนุกรมเวลาของค่าจากเซ็นเซอร์วัดการเคลื่อนไหวที่เก็บ 200 ครั้งต่อวินาที โดยมี `ax, ay, az` หน่วยเป็น g และ `wx, wy, wz` หน่วยเป็นองศาต่อวินาที และเขียนว่า "Each `id` corresponds to one yoga repetition." คือหนึ่ง `id` คือการทำท่าหนึ่งครั้ง

แต่พอดูส่วนตัวอย่างในไฟล์เดียวกัน จะเห็นว่าแถว `0`, `1`, `2` แต่ละแถวมี `id` *ต่างกัน* มีคอลัมน์สัญญาณหกคอลัมน์ และไม่มีคอลัมน์เวลาเลย

**ตัวโจทย์ขัดกันเอง** เพราะคำบรรยายบอกว่าแต่ละการทำท่ามีอนุกรมเวลา คือหลายแถวใช้ `id` เดียวกัน แต่ตัวอย่างแสดงว่าหนึ่งแถวคือหนึ่งการทำท่า ทั้งสองอย่างเป็นจริงพร้อมกันในไฟล์เดียวกันไม่ได้

เรื่องนี้ไม่ใช่ปริศนาที่ต้องนั่งคิด แต่เป็นสิ่งที่ต้องวัดเอา คำสั่งแรกที่ควรพิมพ์ในสนามสอบคือ `X_test.groupby("id").size().max()`

- **ถ้าได้ค่ามากกว่า 1** แปลว่าคำบรรยายถูก คือมีหน้าต่างข้อมูลจริง และบทเรียนนี้ *คือ* ตัวโจทย์เลย ให้สรุปข้อมูลด้วยชุดคุณลักษณะข้างต้น
- **ถ้าได้ค่าเท่ากับ 1** แปลว่าตัวอย่างถูก คือแต่ละแถวเป็นตัวอย่างอยู่แล้ว ให้ข้ามไปทำเรื่องการสร้างคุณลักษณะในบท T16 กับข้อมูลหกคอลัมน์ และทุกบรรทัด `groupby` ที่เขียนไว้จะกลายเป็นโค้ดที่ไม่ถูกใช้งาน

ควรตรวจอีกอย่างหนึ่งด้วย คือ `X_train.groupby("id").size().describe()` ถ้าหน้าต่างแต่ละอันยาวไม่เท่ากัน ค่า `n_rows` จะกลายเป็นคุณลักษณะที่มีความหมายในตัวเอง เพราะระยะเวลาอาจแยกท่าที่ถูกออกจากท่าที่ผิดได้ และยังตัดความเป็นไปได้ของโมเดลที่ต้องการข้อมูลเข้าความยาวคงที่ออกไป นอกจากนี้ เนื่องจากไม่มีคอลัมน์เวลา ลำดับของแถว *คือ* ลำดับของเวลา ดังนั้นห้ามเรียงใหม่หรือสับแถวก่อนคำนวณสิ่งใดก็ตามที่ขึ้นกับลำดับ

ไฟล์ที่ต้องส่งคือ `solution.csv` ที่มีคอลัมน์ `id,label` โดยโจทย์ระบุว่า "strictly follow the order in `test.csv`, starting from `0`" คือให้เรียงตามลำดับใน `test.csv` อย่างเคร่งครัด เริ่มจาก `0` และวัดผลด้วยความแม่นยำธรรมดา ไม่ว่าขั้นตอนก่อนหน้าจะเป็นอย่างไร สิ่งที่ต้องส่งคือคำตอบหนึ่งค่าต่อหนึ่ง `id` เรียงตาม `id` จากน้อยไปมาก

## [code-first] โค้ดที่รันได้ พร้อมคำอธิบายในคอมเมนต์

```python
import numpy as np
import pandas as pd

SIG = ["ax", "ay", "az", "wx", "wy", "wz"]
FS = 200                                     # Hz ตามที่โจทย์ระบุ: 200 แถวเท่ากับ 1 วินาที

X = pd.read_csv("X_train.csv")

# คำสั่งแรกของการสอบ: ข้อมูลนี้มีหน้าต่างข้อมูลจริงหรือไม่
sizes = X.groupby("id").size()
print("rows/id:", sizes.min(), sizes.median(), sizes.max(), "| seconds:", sizes.max() / FS)
if sizes.max() == 1:
    raise SystemExit("One row per id: no windows. Go to T16 instead.")

zcr = lambda s: float(np.mean(np.sign(s.values[:-1]) != np.sign(s.values[1:]))) if len(s) > 1 else 0.0
rms = lambda s: float(np.sqrt(np.mean(s.values ** 2)))
rng = lambda s: float(s.max() - s.min())

def featurise(X):
    X = X.copy()
    # คำนวณขนาดรวมก่อน เพราะค่านี้ไม่เปลี่ยนตามวิธีติดเซ็นเซอร์บนร่างกาย
    X["amag"] = np.sqrt(X.ax**2 + X.ay**2 + X.az**2)
    X["wmag"] = np.sqrt(X.wx**2 + X.wy**2 + X.wz**2)
    cols = SIG + ["amag", "wmag"]

    g = X.groupby("id")
    agg = g[cols].agg(["mean", "std", "min", "max", rms, rng, zcr])
    agg.columns = ["_".join(map(str, c)) for c in agg.columns]   # ยุบชื่อคอลัมน์ให้แบนทันที
    agg["n_rows"] = g.size()                                    # ใช้ระยะเวลาเป็นคุณลักษณะหนึ่งตัว
    # การประสานกัน: คุณลักษณะเดียวที่มองเห็นว่าแกนต่าง ๆ ขยับพร้อมกันหรือไม่
    for a, b in [("ax", "ay"), ("ax", "az"), ("wx", "wy"), ("amag", "wmag")]:
        agg[f"corr_{a}_{b}"] = g.apply(lambda d: d[a].corr(d[b]))
    return agg.fillna(0)                       # กลุ่มที่มีแถวเดียวจะได้ std และ corr เป็น NaN

F = featurise(X).sort_index()                  # หนึ่งแถวต่อหนึ่ง id เท่ากับจัดกลุ่มเรียบร้อยแล้ว
y = pd.read_csv("y_train.csv").set_index("id").loc[F.index, "label"]
# ตอนนี้ใช้ train_test_split ธรรมดาได้อย่างปลอดภัย ถ้าใช้กับข้อมูลดิบทีละแถวจะเกิดข้อมูลรั่วทันที
```

## ข้อควรระวัง และสรุปสำหรับอ่านทบทวน 60 วินาที

- 200 Hz แปลว่า 200 แถวต่อหนึ่งวินาที และระยะเวลาคือ $n_{\text{rows}} / 200$
- สรุปข้อมูลให้เหลือหนึ่งแถวต่อหนึ่ง `id` *ก่อน* สร้างโมเดล เพราะการทำแบบนี้แก้ทั้งปัญหารูปร่างข้อมูลและปัญหาข้อมูลรั่วพร้อมกันในคราวเดียว
