**ตัววัดผลของการแข่งขัน (competition metric)** คือ สูตรที่ผู้จัดการแข่งขันกำหนดไว้เองว่าจะให้คะแนนคำตอบของเราอย่างไร ซึ่งอาจไม่ใช่สูตรมาตรฐานที่มีอยู่ในไลบรารีทั่วไป

ตัววัดผลเป็นส่วนหนึ่งของโจทย์ ไม่ใช่รายละเอียดปลีกย่อยที่ค่อยอ่านทีหลัง โจทย์ในคลังข้อสอบนี้สามข้อกำหนดสูตรให้คะแนนของตัวเอง และแต่ละสูตรให้รางวัลกับพฤติกรรมที่ต่างกันโดยสิ้นเชิง การอ่านสูตรให้เข้าใจก่อนลงมือ จึงเปลี่ยนวิธีแก้โจทย์ทั้งข้อได้

## [concept-first] ทฤษฎีก่อน แล้วดูตัวอย่าง

**วิธีอ่านนิยามของตัววัดผล** มีคำถามสี่ข้อที่ต้องถามตามลำดับ

1. **หน่วยของการให้คะแนนคืออะไร** ให้ถามว่าคะแนนคิดต่อหนึ่งแถว ต่อหนึ่งผู้ใช้ ต่อหนึ่งภาพ หรือต่อหนึ่งคำค้น ตัวอย่างเช่น [`Lost_in_the_Museum.md`](../faio-2025/day2/Lost_in_the_Museum.md) ให้คะแนนต่อหนึ่ง **คำค้น (query)** ซึ่งมีทั้งหมด 1,000 คำค้น ถึงแม้ไฟล์คำตอบที่เราส่งจะมีถึง 20,000 แถวก็ตาม

2. **ความผิดพลาดคิดแบบสัมพัทธ์หรือแบบสัมบูรณ์** ความผิดพลาดแบบสัมบูรณ์ (absolute error) นับว่า "ผิดไป 5" มีค่าเท่ากันเสมอไม่ว่าคำตอบจริงจะเป็นเท่าไร ส่วนความผิดพลาดแบบสัมพัทธ์ (relative error) จะหารด้วยคำตอบจริง ดังนั้นการผิดไป 5 บนคำตอบจริง 100 จะเสียคะแนนมากกว่าการผิดไป 5 บนคำตอบจริง 500 ถึงห้าเท่า

3. **มีเพดาน มีพื้น หรือมีเกณฑ์ตัดหรือไม่** ฟังก์ชัน $\min(1, \cdot)$ ทำหน้าที่เป็นเพดานจำกัดความเสียหายต่อหนึ่งตัวอย่าง ส่วนพื้นที่ใช้ปรับสเกล (rescaling floor) สามารถเปลี่ยนคะแนนที่ดูพอใช้ได้ให้กลายเป็นศูนย์สนิทได้เลย

4. **รวมคะแนนของแต่ละตัวอย่างอย่างไร** ให้ดูว่าเป็นค่าเฉลี่ย ผลรวม หรือค่าเฉลี่ยของผลรวมรายกลุ่ม ข้อนี้เป็นตัวตัดสินว่าคลาสที่พบน้อย หรือผู้ใช้ที่ใช้งานน้อย จะมีความสำคัญมากหรือน้อยเพียงใด

**ความถูกต้องแบบคิดจากความผิดพลาดสัมพัทธ์ (relative-error accuracy)** คือ สูตรที่ใช้ใน [`task6_Simple_Objects.md`](../faio-2025/qualification/task6_Simple_Objects.md) โจทย์นี้ให้นับจำนวนวัตถุในภาพ แล้ววัดว่าจำนวนที่นับได้ห่างจากความจริงกี่เปอร์เซ็นต์

$$
\text{Error Rate} = \frac{\lvert \hat{y} - y \rvert}{y}
$$

เมื่อ $\hat{y}$ คือ จำนวนที่เราทำนาย, $y$ คือ จำนวนจริง และเครื่องหมาย $\lvert \cdot \rvert$ คือ ค่าสัมบูรณ์ ซึ่งหมายถึงการตัดเครื่องหมายลบทิ้ง ทำให้การนับเกินและการนับขาดถูกลงโทษเท่ากัน

$$
\text{Accuracy} = 1 - \min(1, \text{Error Rate})
$$

เมื่อ $\min(1, \cdot)$ คือ การเลือกค่าที่น้อยกว่าระหว่าง 1 กับอัตราความผิดพลาด ผลคือความผิดพลาดที่เกิน 100% จะถูกตัดให้เหลือ 100% พอดี ค่า accuracy ต่อหนึ่งภาพจึงอยู่ระหว่าง 0 ถึง 1 เสมอ

$$
\text{Final} = \frac{\text{Accuracy} - 0.55}{1 - 0.55}
$$

เมื่อ $\text{Accuracy}$ ในสูตรนี้คือค่าเฉลี่ยจากทุกภาพ และเลข 0.55 คือ **พื้นสำหรับปรับสเกล (rescaling floor)** ซึ่งหมายถึงค่าที่ถือว่าเป็นจุดเริ่มต้นของการได้คะแนน

ผลที่ตามมาจากสูตรชุดนี้มีสามข้อ ข้อแรก การที่มี $\min(1, \cdot)$ แปลว่าการทำนายเกินไปมหาศาลเสียคะแนนเท่ากับการทำนายเป็นศูนย์พอดี และคะแนนของหนึ่งภาพติดลบไม่ได้ ข้อสอง การหารด้วย $y$ แปลว่างานนี้เป็นการนับแบบคิดตามสัดส่วน บนภาพที่มีวัตถุ 100 ชิ้น การพลาดไป 2 ชิ้นเสียคะแนนเท่ากับการพลาดไป 10 ชิ้นบนภาพที่มี 500 ชิ้น ข้อสาม พื้นที่ 0.55 ทำหน้าที่ปรับสเกล คือ accuracy เท่ากับ 0.55 จะถูกแปลงเป็นคะแนน 0 และ accuracy เท่ากับ 1.0 จะถูกแปลงเป็นคะแนน 1 ดังนั้นคำตอบที่ได้ accuracy เฉลี่ย 0.50 จะได้คะแนนเท่ากับศูนย์ ไม่ได้อะไรเลย

**เอกสารของโจทย์ข้อนี้ขัดแย้งกันเอง** กฎการตัดสินที่พิมพ์ไว้เขียนว่าให้ $0$ เมื่อ $\text{Accuracy} > 0.55$ แล้วเอาสูตรปรับสเกลไปไว้ในกรณี `otherwise` ถ้าอ่านตามตัวอักษรจริง ๆ จะกลายเป็นว่าทำได้ดีแล้วได้ 0 และทำได้แย่แล้วได้ค่าติดลบ ซึ่งกลับหัวกลับหางอย่างชัดเจน การตีความที่สมเหตุสมผลคือกลับกัน กล่าวคือ **ได้ 0 เมื่อ accuracy ต่ำกว่า 0.55** และใช้สูตรปรับสเกลเมื่อสูงกว่านั้น ให้ยึดการตีความแบบนี้ แล้วทำคะแนนให้เหนือ 0.55 ไปให้ห่าง ๆ เพื่อที่ความคลุมเครือนี้จะทำอะไรเราไม่ได้

**ตัววัดผลแบบจัดอันดับ (ranking metric)** คือ สูตรที่ให้คะแนนตามว่าคำตอบที่ถูกต้องถูกจัดให้อยู่อันดับต้น ๆ หรือไม่ โจทย์ [`Lost_in_the_Museum.md`](../faio-2025/day2/Lost_in_the_Museum.md) ใช้ตัววัดชื่อ **Hit@3** ซึ่งทำงานแบบนี้ สำหรับแต่ละคำค้นจากทั้งหมด 1,000 คำค้น ให้เรียงลำดับเวกเตอร์ของภาพในแกลเลอรีและภาพหลอกรวม 19,000 ชิ้น ตามค่าความคล้ายแบบโคไซน์ (cosine similarity — ตัวเลขบอกว่าเวกเตอร์สองตัวชี้ไปทางเดียวกันแค่ไหน) แล้วให้คะแนน 1 ถ้าคำตอบที่ถูกต้องติดอยู่ในสามอันดับแรก และให้ 0 ถ้าไม่ติด

$$
\text{Hit@3} = \frac{\text{hits}}{1000}
$$

เมื่อ $\text{hits}$ คือ จำนวนคำค้นที่คำตอบถูกต้องติดสามอันดับแรก และ 1000 คือ จำนวนคำค้นทั้งหมด

สมบัติที่ตามมามีสองข้อ ข้อแรก ตัววัดนี้เป็นแบบ **ได้หรือไม่ได้ ต่อหนึ่งคำค้น** อันดับ 1 กับอันดับ 3 ได้คะแนนเท่ากันเป๊ะ ส่วนอันดับ 4 ไม่ได้อะไรเลย ดังนั้นการไปขัดเกลาผลลัพธ์ที่ถูกต้องอยู่แล้วให้ขึ้นมาอันดับ 1 จึงไม่ได้คะแนนเพิ่มแม้แต่นิดเดียว ข้อสอง สิ่งที่เราส่งคือ **เวกเตอร์ ไม่ใช่คำทำนาย** การจัดอันดับเกิดขึ้นบนเครื่องของผู้จัดการแข่งขัน ค่าความคล้ายแบบโคไซน์ไม่ขึ้นกับขนาดของเวกเตอร์ ดังนั้นการทำ L2-normalisation (การปรับความยาวของเวกเตอร์ให้เท่ากับ 1) ไม่เปลี่ยนผลทางคณิตศาสตร์ แต่โจทย์ระบุว่าชอบให้ส่งแบบที่ปรับแล้วมากกว่า จึงควรทำ เพราะใช้โค้ดเพียงบรรทัดเดียวและตัดความเสี่ยงเรื่องตัวเลขผิดเพี้ยนออกไปได้

**ตัววัดผลแบบให้คะแนนบางส่วนแล้วรวมกัน** คือ รูปแบบที่ใช้ใน [`HearMe_Personalized_Music_Recommender.md`](../faio-2025/day2/HearMe_Personalized_Music_Recommender.md) โจทย์นี้ให้เราแนะนำเพลง 50 เพลงต่อผู้ใช้หนึ่งคน แล้วให้คะแนนแต่ละเพลงตามสัดส่วนที่ผู้ใช้ฟังจริง ซึ่งเป็นค่าใน $\{0,\ 0.25,\ 0.5,\ 0.75,\ 1.0\}$ จากนั้นรวมคะแนนของ 50 เพลงเข้าด้วยกันต่อผู้ใช้หนึ่งคน ได้ค่าในช่วง 0 ถึง 50 แล้วหาค่าเฉลี่ยข้ามผู้ใช้ทุกคน สุดท้ายปรับสเกลให้อยู่ในช่วง 0 ถึง 1

ผลที่ตามมาคือ มีคะแนนบางส่วนจริง การฟังไปหนึ่งในสี่ได้คะแนนหนึ่งในสี่จริง ๆ การฟังซ้ำไม่นับซ้ำ และที่สำคัญที่สุดคือ **ตำแหน่งอันดับภายใน 50 เพลงไม่มีน้ำหนักเลย** เพลงอันดับ 1 กับเพลงอันดับ 50 มีค่าเท่ากัน นั่นทำให้โจทย์นี้เป็นปัญหาการ *เลือกชุด* ไม่ใช่ปัญหาการ *เรียงลำดับ* และสิ่งที่ควรพยายามทำนายคือความลึกของการฟัง ไม่ใช่แค่การคลิกเข้าไปฟัง

**macro-F1** ซึ่งเป็นตัววัดผลจริงของ task 4 มีสูตรอยู่ใน [`day03_t05_math_classification_metrics_formula_only.md`](./day03_t05_math_classification_metrics_formula_only.md) แล้ว ประเด็นที่ต้องรู้ในบทนี้มีเพียงข้อเดียว คือ โจทย์ [`task4_Who_Speaks_What.md`](../faio-2025/qualification/task4_Who_Speaks_What.md) ไม่เคยบอกเลยว่าใช้ตัววัดผลอะไร ต้องไปอนุมานเอาจากไฟล์เฉลย ซึ่งเรียก `classification_report` และตั้ง `scoring="f1_macro"` ในการค้นหาพารามิเตอร์ บทเรียนคือ เมื่อโจทย์เงียบเรื่องตัววัดผล ให้ไปอ่านโค้ดตัวอย่างที่แถมมากับโจทย์

## [problem-first] เริ่มจากโจทย์จริง แล้วหาว่าต้องรู้อะไร

เปิดไฟล์ [`task6_Simple_Objects.md`](../faio-2025/qualification/task6_Simple_Objects.md) แล้ววางแผนการแก้โจทย์จากสูตรให้คะแนนเพียงอย่างเดียว ก่อนที่จะแตะภาพสักภาพ

1. ความผิดพลาดคิดแบบสัมพัทธ์ ดังนั้น **ภาพที่มีวัตถุจำนวนมากให้อภัยง่าย ส่วนภาพที่มีวัตถุน้อยโหดมาก** ถ้าเราคิดแบบความผิดพลาดสัมบูรณ์ตามสัญชาตญาณ เราจะไปปรับโมเดลกับภาพผิดกลุ่ม วิธีที่ถูกต้องคือแบ่งชุดตรวจสอบโดยแบ่งชั้นตามจำนวนวัตถุจริง (stratified validation — การแบ่งข้อมูลให้ทุกส่วนมีสัดส่วนของแต่ละกลุ่มใกล้เคียงกัน)

2. ฟังก์ชัน $\min(1, \cdot)$ จำกัดความเสียหายไว้ ดังนั้นความล้มเหลวรุนแรงบนภาพเดียวก็ยังมีขอบเขต ห้ามข้ามภาพใดเด็ดขาด ให้ตอบตัวเลขที่พอเป็นไปได้ออกมาเสมอ แม้แต่การตอบด้วยค่าเฉลี่ยของชุดสอนก็ยังดีกว่าการไม่ตอบอะไรเลย

3. ความคลาดเคลื่อนที่เป็นระบบจะกินคะแนนทุกภาพพร้อมกัน ตัวอย่างเช่น ถ้าเรานับเกินไป 5% เท่ากันทุกภาพ คะแนนจะเป็น $(0.95 - 0.55)/0.45 = 0.8889$ และความคลาดเคลื่อนแบบนี้แก้ได้ฟรี วิธีแก้คือวัดค่า `mean(pred/true)` บนภาพชุดสอน แล้วเอาค่านั้นไปหารคำตอบก่อนส่ง นี่คือคะแนนที่ได้มาถูกที่สุดในโจทย์ข้อนี้

4. พื้นที่ 0.55 เป็นหน้าผา อะไรก็ตามที่ทำคะแนนได้ต่ำกว่านั้นมีค่าเท่ากับการส่งไฟล์เปล่า ดังนั้นคำตอบที่ทำแบบลวก ๆ จะไม่ได้คะแนนเลย ไม่ใช่ได้คะแนนน้อย

5. โจทย์ข้อนี้ยังเป็นข้อเดียวในคลังที่ระบุกฎเรื่องเครื่องมือไว้ชัดเจนว่า "คุณจะใช้ภาษาโปรแกรมและไลบรารีใดก็ได้ เช่น OpenCV, scikit-image, PIL เป็นต้น"

## [code-first] โค้ดที่รันได้ พร้อมคำอธิบายในคอมเมนต์

```python
import numpy as np

# เขียนสูตรให้คะแนนขึ้นมาเองก่อนลงมือทำโมเดล นี่คือนิสัยที่ต้องสร้าง ที่เหลือเป็นรายละเอียด
def task6_score(y_true, y_pred, floor=0.55):
    y_true, y_pred = np.asarray(y_true, float), np.asarray(y_pred, float)
    err = np.abs(y_pred - y_true) / y_true          # แบบสัมพัทธ์ คือ หารด้วยคำตอบจริง
    acc = 1.0 - np.minimum(1.0, err)                # จำกัดความเสียหายไว้ที่ 1 ต่อหนึ่งภาพ
    acc = acc.mean()
    return max(0.0, (acc - floor) / (1.0 - floor))  # ตีความพื้น 0.55 แบบที่สมเหตุสมผล

def hit_at_k(q_emb, g_emb, true_idx, k=3):
    # Lost in the Museum: โคไซน์บนเวกเตอร์ที่ปรับความยาวแล้ว ก็คือผลคูณจุดธรรมดา
    q = q_emb / np.linalg.norm(q_emb, axis=1, keepdims=True)
    g = g_emb / np.linalg.norm(g_emb, axis=1, keepdims=True)
    top = np.argsort(-(q @ g.T), axis=1)[:, :k]
    return float(np.mean([t in row for t, row in zip(true_idx, top)]))

def hearme_score(recs, listened, n_items=50):
    # recs: {ผู้ใช้: [เพลง, ...]}  listened: {(ผู้ใช้, เพลง): สัดส่วนที่ฟัง 0..1}
    per_user = [sum(listened.get((u, i), 0.0) for i in items[:n_items])
                for u, items in recs.items()]
    return float(np.mean(per_user)) / n_items       # แปลงช่วง 0..50 ให้เป็น 0..1

# ทดสอบสูตรให้คะแนนกับคำตอบพื้นฐานที่รู้ผลอยู่แล้วทุกครั้ง ก่อนจะเชื่อมัน
y = np.array([100, 250, 500])
print(task6_score(y, y))                            # ได้ 1.0 คือคำตอบที่สมบูรณ์แบบ
print(task6_score(y, np.full(3, y.mean())))         # เส้นฐานแบบตอบค่าเฉลี่ยเท่ากันทุกภาพ
print(task6_score(y, y * 1.05))                     # นับเกินเป็นระบบ 5% ได้ 0.8889
```

## ข้อควรระวัง และสรุปสำหรับอ่านทบทวน 60 วินาที

- เขียนสูตรให้คะแนนขึ้นมาใช้เองบนเครื่องก่อนเริ่มทำโมเดลเสมอ ถ้าข้ามขั้นตอนนี้ ทุกข้อที่เหลือในรายการนี้ก็ไม่มีความหมาย
- ความผิดพลาดแบบสัมพัทธ์ทำให้ตัวอย่างที่มีค่าจริงน้อยมีอิทธิพลต่อคะแนนมากที่สุด ให้แบ่งชุดตรวจสอบโดยแบ่งชั้นตามขนาดของคำตอบจริง
- ฟังก์ชัน $\min(1, \cdot)$ จำกัดความเสียหายต่อหนึ่งตัวอย่าง ดังนั้นให้ตอบตัวเลขออกมาเสมอ ห้ามเว้นว่าง
