แหล่งอ้างอิงภายนอก คือ mlcourse.ai หัวข้อที่ 5 ชื่อ "Bagging and random forest" ซึ่งไม่ได้ดึงเนื้อหามาไว้ที่นี่ เพราะเว็บไซต์ถูกปิดกั้นจากสภาพแวดล้อมนี้

**Bagging (การรวมผลจากหลายโมเดลที่สอนด้วยข้อมูลสุ่ม)** คือ การสอนโมเดลชนิดเดียวกันหลายตัว โดยแต่ละตัวเห็นข้อมูลที่สุ่มมาไม่เหมือนกัน แล้วนำคำตอบของทุกตัวมาเฉลี่ยหรือโหวตกัน

**Random forest (ป่าสุ่ม)** คือ การทำ bagging กับต้นไม้ตัดสินใจ พร้อมกับเพิ่มการสุ่มเลือกคอลัมน์ในทุกจุดแยกเข้าไปอีกชั้นหนึ่ง

ต้นไม้ลึกต้นเดียวตามที่เรียนใน T10 มีลักษณะที่เรียกว่า bias ต่ำแต่ variance สูง โดย **bias (ความลำเอียง)** คือ ความผิดพลาดที่เกิดจากโมเดลเรียบง่ายเกินกว่าจะจับรูปแบบจริงได้ และ **variance (ความแปรปรวน)** คือ ความผิดพลาดที่เกิดจากผลของโมเดลเปลี่ยนไปมากเมื่อข้อมูลสอนเปลี่ยนไปเพียงเล็กน้อย ต้นไม้ลึกจึงจับรูปแบบได้ดีแต่เปลี่ยนรูปร่างทั้งต้นเมื่อสลับข้อมูลสอนไม่กี่แถว bagging ถูกออกแบบมาโจมตี variance ตัวนี้โดยตรง

## [concept-first] ทฤษฎีก่อน แล้วดูตัวอย่าง

- **Bootstrap (การสุ่มเลือกแถวแบบคืนที่)** คือ การสุ่มหยิบข้อมูล $n$ แถวจากข้อมูลสอนที่มี $n$ แถว โดยหยิบแล้วใส่คืนทุกครั้ง ผลคือบางแถวถูกหยิบซ้ำและบางแถวไม่ถูกหยิบเลย ตัวอย่างที่ได้แต่ละชุดจะมีแถวที่ไม่ซ้ำกันประมาณ 63.2% ซึ่งมาจาก $1 - (1 - 1/n)^n \to 1 - e^{-1}$ ที่เหลือเป็นแถวซ้ำ จากนั้นฟิตต้นไม้หนึ่งต้นต่อหนึ่งชุด แล้วนำคำตอบมาเฉลี่ยกัน สำหรับงานแบ่งกลุ่มจะใช้การโหวตเสียงข้างมาก หรือเฉลี่ยความน่าจะเป็น

- **เหตุผลที่การเฉลี่ยช่วยลด variance** อธิบายได้ด้วยสูตรต่อไปนี้ สำหรับตัวทำนาย $B$ ตัวที่แต่ละตัวมีความแปรปรวน $\sigma^2$ และมีค่าสหสัมพันธ์ระหว่างคู่เท่ากับ $\rho$

$$
\operatorname{Var}(\text{mean}) = \rho\sigma^2 + \frac{(1 - \rho)\sigma^2}{B}
$$

เมื่อ $B$ คือ จำนวนต้นไม้, $\sigma^2$ คือ ความแปรปรวนของต้นไม้หนึ่งต้น และ $\rho$ คือ ค่าสหสัมพันธ์ระหว่างต้นไม้สองต้น คือตัวเลขที่บอกว่าต้นไม้ทำนายเหมือนกันแค่ไหน

การเพิ่ม $B$ ทำให้พจน์ที่สองเล็กลงจนแทบหมดไป แต่ไม่ช่วยพจน์แรกเลย ดังนั้นประโยชน์ที่ได้จึงขึ้นอยู่กับการทำให้ต้นไม้ **แตกต่างกัน** ให้มากที่สุด และการทำ bootstrap อย่างเดียวยังทำให้ต้นไม้คล้ายกันอยู่มาก เพราะคุณลักษณะที่แข็งแรงที่สุดตัวหนึ่งมักถูกเลือกไปอยู่ที่รากของต้นไม้แทบทุกต้น

- **การสุ่มเลือกคุณลักษณะ คือสิ่งที่ทำให้มันเป็นป่า *สุ่ม*** ที่ทุกจุดแยก โมเดลจะพิจารณาเพียงคอลัมน์ที่สุ่มมาจำนวน `max_features` ตัวเท่านั้น นี่คือแหล่งความสุ่มที่สองและเป็นตัวที่กด $\rho$ ให้ต่ำลงจริง ค่าเริ่มต้นคือ $\sqrt{p}$ คอลัมน์สำหรับงานแบ่งกลุ่ม และ $p$ หรือ `1.0` สำหรับงานทำนายตัวเลข เมื่อ $p$ คือจำนวนคอลัมน์ทั้งหมด

สรุปได้ว่า random forest เท่ากับ bagging ของต้นไม้ลึก บวกกับการสุ่มเลือกคุณลักษณะที่ทุกจุดแยก ค่า bias ยังคงอยู่ราวเท่ากับต้นไม้ลึกหนึ่งต้น แต่ variance ลดลงมาก นี่คือเหตุผลที่ให้ปลูกต้นไม้ **ลึก** โดยตั้ง `max_depth=None` แล้วไปควบคุมการจำมากเกินไปด้วย `n_estimators` และ `min_samples_leaf` แทน

- **Out-of-bag estimate (การประเมินจากแถวที่ไม่ถูกหยิบ)** คือ คะแนนตรวจสอบที่ได้มาฟรี แต่ละแถวถูกละไว้จากชุด bootstrap ประมาณ 36.8% ของทั้งหมด จึงสามารถทำนายแถวนั้นด้วยเฉพาะต้นไม้ที่ไม่เคยเห็นมันเลย การตั้ง `oob_score=True` จะให้ค่า `rf.oob_score_` โดยไม่ต้องฟิตเพิ่มแม้แต่ครั้งเดียว วิธีนี้ใช้ตรวจความสมเหตุสมผลได้ดี แต่มันจัดกลุ่มไม่ได้และแบ่งตามสัดส่วนคำตอบไม่ได้ ดังนั้นสำหรับ task 5 มันจึงใช้แทน `GroupKFold` ตาม T07 ไม่ได้

- **`feature_importances_` (ค่าความสำคัญของคุณลักษณะ)** คือ ตัวเลขที่บอกว่าแต่ละคอลัมน์มีส่วนช่วยมากแค่ไหน ค่าเริ่มต้นคำนวณจากการลดลงของความไม่บริสุทธิ์โดยเฉลี่ย คือรวมค่าความไม่บริสุทธิ์ที่คอลัมน์นั้นช่วยลดได้จากทุกต้นไม้ แล้วปรับให้ผลรวมเป็น 1 ให้อ่านค่านี้เป็นเพียงการจัดอันดับ ไม่ใช่ความจริง เพราะมันมีความลำเอียงสองอย่าง หนึ่งคือมันให้คะแนนสูงเกินจริงกับคอลัมน์ที่เป็นตัวเลขต่อเนื่องหรือมีค่าต่างกันมาก เพราะมีเกณฑ์ให้ลองแบ่งมากกว่า และสองคือมันแบ่งเครดิตให้คอลัมน์ที่ซ้ำกัน ทำให้คุณลักษณะที่ดีจริงแต่ปรากฏสองครั้งได้อันดับต่ำทั้งสองครั้ง วิธีที่ตรงไปตรงมากว่าคือ `permutation_importance` ซึ่งวัดบนข้อมูลที่กันไว้ ใช้เมื่อมีเวลาเหลือ

- **เมื่อใด random forest ชนะต้นไม้ต้นเดียว** คำตอบคือชนะเสมอในแง่ความแม่นยำ โดยแลกกับการที่อ่านเข้าใจยากขึ้นและใช้เวลามากขึ้น ส่วนกรณีที่มันแพ้ boosting ตาม T12 คือกับข้อมูลตารางที่สร้างคุณลักษณะมาดีแล้วเกือบทุกชุด แพ้ด้วยส่วนต่างเล็กน้อยแต่มีจริง เพราะ boosting ลดทั้ง bias และ variance ข้อได้เปรียบของ random forest คือมันแทบเป็นไปไม่ได้เลยที่จะตั้งค่าผิด

## [code-first] โค้ดที่รันได้ พร้อมคำอธิบายในคอมเมนต์

```python
import numpy as np
import pandas as pd
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.inspection import permutation_importance

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

rf = RandomForestClassifier(
    n_estimators=500,      # ยิ่งมากยิ่งไม่แย่ลง เพียงแต่ช้าลง ไม่ใช่ปุ่มที่ทำให้จำเกิน
    max_features="sqrt",   # ปุ่มที่ทำให้ต้นไม้ต่างกัน และเป็นค่าเริ่มต้นของงานแบ่งกลุ่ม
    max_depth=None,        # ตั้งใจปลูกให้ลึก เพราะการเฉลี่ยจะจัดการความแปรปรวนเอง
    min_samples_leaf=1,    # เพิ่มเป็น 2 ถึง 5 เมื่อข้อมูลน้อยหรือมีสัญญาณรบกวนมาก
    n_jobs=-1,             # ใช้ทุกแกนของซีพียู เป็นการลดเวลารอที่ได้ผลมากที่สุด
    oob_score=True,        # คะแนนตรวจสอบที่ได้ฟรีจากแถวที่ไม่ถูกหยิบ ประมาณ 36.8%
    random_state=42,
)

print("CV :", cross_val_score(rf, X, y, cv=cv, scoring="accuracy").mean())

print("OOB:", rf.oob_score_)   # ควรใกล้เคียงกับคะแนน CV ถ้าไม่ใกล้ให้สงสัยว่าข้อมูลรั่ว

# ค่าความสำคัญแบบความไม่บริสุทธิ์ เป็นแค่การจัดอันดับ และลำเอียงเข้าหาคอลัมน์ตัวเลขต่อเนื่อง
imp = pd.Series(rf.feature_importances_, index=X.columns).sort_values(ascending=False)
print(imp.head(15))

# วิธีที่ตรงไปตรงมากว่า เพราะวัดบนแถวที่กันไว้ ไม่ได้วัดจากความไม่บริสุทธิ์ของข้อมูลสอน
pi = permutation_importance(rf, X_val, y_val, n_repeats=10, random_state=42)
print(pd.Series(pi.importances_mean, index=X.columns).sort_values(ascending=False).head(15))

# ไล่ค่า n_estimators จะเห็นว่าเส้นกราฟค่อย ๆ ราบลง ไม่ได้ย้อนกลับลงมา
for B in (10, 50, 100, 300, 500):
    m = RandomForestClassifier(n_estimators=B, n_jobs=-1, random_state=42)
    print(B, cross_val_score(m, X, y, cv=cv).mean())
```

## [drill] แบบฝึกหัด

1. ชุด bootstrap หนึ่งชุดมีแถวที่ไม่ซ้ำกันเป็นสัดส่วนเท่าไร และตัวเลขนั้นมาจากไหน
2. เพราะเหตุใดการเพิ่ม `n_estimators` จึงไม่ทำให้เกิดการจำมากเกินไป ในขณะที่การเพิ่ม `max_depth` ของต้นไม้ต้นเดียวทำให้เกิด
3. การตั้ง `max_features="sqrt"` ให้ประโยชน์อะไรที่การทำ bootstrap อย่างเดียวให้ไม่ได้
4. คะแนน OOB ได้ 0.95 แต่คะแนนจาก `GroupKFold` ได้ 0.71 เกิดอะไรขึ้น
5. คุณลักษณะที่รู้แน่ว่ามีประโยชน์กลับได้ค่าความสำคัญเพียง 0.004 จงบอกสาเหตุที่เป็นไปได้สองข้อ
6. จงบอกสองสถานการณ์ที่ควรเลือก random forest แทน gradient boosting ในการสอบที่จับเวลา

3. ให้ความแตกต่างระหว่างต้นไม้ เพราะถ้าทุกคุณลักษณะถูกพิจารณาได้หมด คอลัมน์ที่แข็งแรงที่สุดตัวเดียวจะถูกเลือกไว้ที่รากเกือบทุกต้น ต้นไม้จึงยังคล้ายกัน และค่าพื้น $\rho\sigma^2$ ยังคงอยู่
4. เพราะ OOB ไม่สามารถรักษากลุ่มไว้ได้ แถวของการทำท่าครั้งเดียวกันใน task 5 จึงไปอยู่ทั้งในชุด bootstrap และในชุด OOB พร้อมกัน ให้เชื่อคะแนนจาก cross-validation ที่จัดกลุ่มแล้ว
5. หนึ่งคือมันสัมพันธ์กับคุณลักษณะอีกตัวที่ดูดเครดิตไปหมด และสองคือวิธีวัดแบบความไม่บริสุทธิ์เข้าข้างคอลัมน์ตัวเลขต่อเนื่องที่มีค่าต่างกันมากมากกว่า ให้ตรวจซ้ำด้วย `permutation_importance`
6. หนึ่งคือเมื่อแทบไม่มีเวลาปรับค่าเลยและต้องการตัวเลขที่อธิบายได้ทันที และสองคือเมื่อข้อมูลน้อยพอ เช่นไม่กี่ร้อยแถวอย่างใน task 5 ซึ่งความสามารถที่มากกว่าของ boosting จะกลายเป็นความแปรปรวนเสียมากกว่า

**แบบฝึกจากโจทย์จริง:** ฟิต random forest 500 ต้นตามโค้ดด้านบนกับคุณลักษณะของ task 5 ที่สรุปแล้ว เปรียบเทียบ `oob_score_` กับคะแนนจาก `StratifiedKFold` พิมพ์ค่าความสำคัญ 15 อันดับแรกออกมาดู จากนั้นตัดคุณลักษณะครึ่งล่างทิ้งแล้ววัดคะแนนใหม่ และจดไว้ว่าความแม่นยำขยับหรือไม่

## ข้อควรระวัง และสรุปสำหรับอ่านทบทวน 60 วินาที

- ชุด bootstrap มีแถวที่ไม่ซ้ำกันประมาณ 63.2% ส่วนอีก 36.8% ที่เหลือกลายเป็นข้อมูลสำหรับคะแนน OOB
- `n_estimators` ยิ่งมากยิ่งปลอดภัย เพียงแต่ช้าลง ส่วน `max_features` คือปุ่มที่ทำให้ต้นไม้แตกต่างกัน
- ปลูกต้นไม้ให้ลึกใน random forest แล้วควบคุมด้วย `min_samples_leaf` ไม่ใช่ด้วย `max_depth`
- ใส่ `n_jobs=-1` ทุกครั้ง เพราะเป็นความเร็วที่ได้มาฟรีในการสอบที่มีเวลา 4 ชั่วโมง
- `feature_importances_` คำนวณจากความไม่บริสุทธิ์ จึงลำเอียงเข้าหาคอลัมน์ตัวเลขต่อเนื่อง และแบ่งเครดิตกันเองระหว่างคอลัมน์ที่สัมพันธ์กัน ให้ใช้จัดอันดับ แต่ตัดสินใจด้วย `permutation_importance`
- คะแนน OOB ไม่จัดกลุ่มและไม่แบ่งตามสัดส่วนคำตอบ สำหรับข้อมูลที่มีกลุ่มอย่าง task 5 มันจึงสูงเกินจริงได้มาก
- random forest คือโมเดลที่ส่งได้เลยโดยไม่ต้องปรับค่า ส่วน boosting ตาม T12 คือโมเดลที่มักชนะเมื่อปรับค่าแล้ว
