ระดับความรู้ 1 · **โอกาสออกสอบ อันดับ 1** · ประมาณ 50 นาที

**Cross-validation (การตรวจสอบแบบไขว้)** คือ วิธีวัดว่าโมเดล (model — โปรแกรมที่เรียนรู้จากข้อมูล) จะทำงานได้ดีแค่ไหนกับข้อมูลที่ไม่เคยเห็นมาก่อน โดยแบ่งข้อมูลออกเป็นหลายส่วนและวัดผลหลายรอบ

**Data leakage (ข้อมูลรั่ว)** คือ สถานการณ์ที่ข้อมูลของชุดวัดผลหลุดเข้าไปในขั้นตอนสอนโมเดล ทำให้คะแนนที่วัดได้สูงเกินความจริง

หัวข้อนี้สำคัญเพราะในวันสอบ คะแนนที่คุณวัดเองคือเครื่องมือเดียวที่ใช้ตัดสินใจได้ ส่วนคะแนนบน leaderboard (กระดานคะแนนของการแข่งขัน) จะมาช้าและมาจากข้อมูลที่คุณมองไม่เห็น ถ้าคะแนนที่วัดเองผิด การตัดสินใจทุกอย่างหลังจากนั้นก็ผิดตามไปด้วย

## [concept-first] ทฤษฎีก่อน แล้วดูตัวอย่าง

วิธีแบ่งข้อมูลเพื่อวัดผลมีหลายแบบ แต่ละแบบเหมาะกับข้อมูลคนละลักษณะ

- **Holdout** คือ การแบ่งข้อมูลออกเป็นสองส่วนเพียงครั้งเดียว ส่วนหนึ่งใช้สอนโมเดล อีกส่วนเก็บไว้วัดผล โดยทั่วไปเก็บไว้วัดผลประมาณ 20% วิธีนี้เร็วที่สุด แต่ผลไม่นิ่ง เพราะถ้าบังเอิญแบ่งได้ข้อมูลที่ไม่ดี คะแนนจะเปลี่ยนไปมากกว่าการปรับโมเดลเสียอีก

- **k-fold** คือ การแบ่งข้อมูลออกเป็น $k$ ส่วนเท่า ๆ กัน แล้ววนสอนและวัดผล $k$ รอบ แต่ละรอบใช้ 1 ส่วนวัดผล และใช้อีก $k-1$ ส่วนสอนโมเดล ผลคือข้อมูลทุกแถวถูกทำนายครบ 1 ครั้ง และใช้เวลาสอนโมเดล $k$ รอบ คะแนนสุดท้ายคือค่าเฉลี่ยของทุกรอบ

$$
\text{CV} = \frac{1}{k}\sum_{i=1}^{k} m_i
$$

  เมื่อ $m_i$ คือ คะแนนของรอบที่ $i$

- **ค่าความคลาดเคลื่อนของคะแนน (standard error)** คือ ตัวเลขที่บอกว่าคะแนนเฉลี่ยที่ได้นั้นแกว่งประมาณเท่าไร ควรรายงานคู่กับค่าเฉลี่ยเสมอ

$$
\text{SE} = \frac{\mathrm{sd}(m_i)}{\sqrt{k}}
$$

  เมื่อ $\mathrm{sd}$ คือ ส่วนเบี่ยงเบนมาตรฐาน (standard deviation — ตัวเลขบอกการกระจายของข้อมูล) ถ้าโมเดลใหม่ได้คะแนนดีขึ้นน้อยกว่าประมาณ $2 \times \text{SE}$ แปลว่ายังไม่ถือว่าดีขึ้นจริง เป็นเพียงความบังเอิญ

- **Stratified k-fold** คือ k-fold ที่บังคับให้ทุกส่วนมีสัดส่วนของแต่ละคำตอบเท่า ๆ กัน เช่น ถ้าข้อมูลทั้งหมดมีคำตอบ 0 อยู่ 70% ทุกส่วนก็จะมีประมาณ 70% ด้วย วิธีนี้เป็นค่ามาตรฐานสำหรับงานแบ่งประเภท (classification)

- **Group k-fold** คือ k-fold ที่กำหนด "คีย์" (key — คอลัมน์ที่ใช้จัดกลุ่ม) แล้วบังคับให้ทุกแถวที่มีคีย์เดียวกันอยู่ในส่วนเดียวกันทั้งหมด วิธีนี้คือหัวใจของบทเรียนนี้ และเป็นวิธีเดียวที่ใช้ได้กับโจทย์ task 5

- **Leave-one-out** คือ กรณีที่ $k$ เท่ากับจำนวนข้อมูลทั้งหมด ให้ผลแม่นยำที่สุดแต่ช้ามาก ไม่เหมาะกับการสอบที่มีเวลา 4 ชั่วโมง

## [problem-first] เริ่มจากโจทย์จริง แล้วหาว่าต้องรู้อะไร

เปิดไฟล์ [`task5_Can_You_Become_AI_Yoga_Instructor.md`](../faio-2025/qualification/task5_Can_You_Become_AI_Yoga_Instructor.md) โจทย์นี้ให้ข้อมูลจากเซ็นเซอร์ติดตัว 6 ค่า คือ `ax ay az wx wy wz` เก็บที่ความถี่ **200 Hz** (200 ครั้งต่อวินาที) โดย 1 `id` คือ การทำท่าโยคะ 1 ครั้ง และต้องทำนายว่าทำถูกหรือผิด

ลองคิดว่าความถี่ 200 Hz ส่งผลอย่างไรกับการวัดผล

1. ถ้าทำท่าหนึ่งใช้เวลา 2 วินาที ข้อมูลของท่านั้นจะมีประมาณ 400 แถว
2. แถวที่อยู่ติดกันห่างกันเพียง 5 มิลลิวินาที เป็นคนเดิม ท่าเดิม ค่าจึงเกือบเหมือนกันทุกประการ
3. ถ้าสับแถวแบบสุ่มแล้วแบ่งเป็นส่วน ๆ ประมาณ 80% ของทุกท่าจะไปอยู่ฝั่งสอนโมเดล
4. แถวที่เหลือไว้วัดผลจึงแทบเป็นแถวเดียวกับที่โมเดลเพิ่งท่องจำไป
5. ผลคือคะแนนออกมาประมาณ 0.99 ซึ่งไม่ได้วัดอะไรเลย

**ข้อสรุป:** คำตอบผูกกับ "การทำท่า 1 ครั้ง" ไม่ได้ผูกกับ "1 แถว" ดังนั้นหน่วยของข้อมูลคือ `id` และต้องใช้ `GroupKFold` หรือ `StratifiedGroupKFold` เท่านั้น

ส่วนโจทย์ [`task4_Who_Speaks_What.md`](../faio-2025/qualification/task4_Who_Speaks_What.md) ข้อมูลรั่วคนละแบบ โจทย์นี้แปลงข้อความเป็นตัวเลขด้วย `TfidfVectorizer` ซึ่งเป็นเครื่องมือที่ **เรียนรู้จากข้อมูล** คือ มันต้องดูข้อความทั้งหมดก่อนเพื่อสร้างรายการคำและคำนวณน้ำหนักของแต่ละคำ ถ้าให้มันดูทั้งข้อมูลสอนและข้อมูลทดสอบพร้อมกัน ข้อมูลทดสอบก็รั่วเข้าโมเดลทันที

วิธีแก้ที่ปลอดภัยที่สุดคือใช้ `Pipeline` (ท่อประมวลผล — เครื่องมือของ scikit-learn ที่ร้อยหลายขั้นตอนเข้าด้วยกัน) เพราะเมื่อใช้ `Pipeline` ระบบจะสร้างตัวแปลงข้อความใหม่ทุกรอบโดยอัตโนมัติ ทำให้ข้อมูลรั่วไม่ได้เลย

## [code-first] โค้ดที่รันได้ พร้อมคำอธิบายในคอมเมนต์

```python
import numpy as np
from sklearn.model_selection import StratifiedGroupKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import HistGradientBoostingClassifier

# --- task 5: หน่วยของข้อมูลคือการทำท่า 1 ครั้ง จึงต้องจัดกลุ่มด้วย id ---
# X_feat = ข้อมูลที่สรุปแล้ว 1 แถวต่อ 1 id, groups = id ของแต่ละแถว
cv = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(
    HistGradientBoostingClassifier(), X_feat, y, groups=groups,
    cv=cv, scoring="accuracy", n_jobs=-1,
)
# รายงานค่าเฉลี่ยพร้อมค่าความคลาดเคลื่อนเสมอ ไม่เช่นนั้นจะแยกไม่ออกว่า
# คะแนนที่ดีขึ้นเป็นของจริงหรือเป็นความบังเอิญ
print(f"{scores.mean():.4f} ± {scores.std(ddof=1) / np.sqrt(len(scores)):.4f}")

# --- task 4: ตัวแปลงข้อความต้องถูกสร้างใหม่ทุกรอบ ---
# Pipeline ทำให้ข้อมูลรั่วไม่ได้ เพราะ cross_val_score จะเรียก fit()
# เฉพาะกับข้อมูลฝั่งสอนเท่านั้น รวมถึงตัวแปลงข้อความด้วย
pipe = make_pipeline(
    TfidfVectorizer(sublinear_tf=True, max_features=20_000),
    LogisticRegression(C=10, solver="saga", max_iter=200, random_state=42),
)
# scoring ต้องตรงกับเกณฑ์ให้คะแนนของการแข่งขัน ไม่ใช่ค่าเริ่มต้น (accuracy)
print(cross_val_score(pipe, texts, labels, cv=5, scoring="f1_macro").mean())

# แบบที่ผิด และเป็นความผิดพลาดที่พบบ่อยที่สุด:
#   X_all = TfidfVectorizer().fit_transform(pd.concat([train.text, test.text]))
# น้ำหนักของคำถูกคำนวณจากข้อมูลทดสอบไปแล้ว คะแนนที่วัดเองจะสูงขึ้น
# แต่คะแนนจริงบน leaderboard จะไม่ขึ้นตาม
```

## [drill] แบบฝึกหัด

1. โจทย์ task 5 ใช้ข้อมูลดิบทีละแถวกับ `KFold` แบบสุ่ม ได้คะแนน 0.99 แต่บน leaderboard ได้ 0.63 สาเหตุคืออะไร และแก้อย่างไร
2. ทำ 5-fold ได้คะแนนรายรอบ 0.80, 0.84, 0.78, 0.86, 0.82 จงหาค่าเฉลี่ยและค่าความคลาดเคลื่อน แล้วตอบว่าโมเดลอีกตัวที่ได้ 0.83 ถือว่าดีกว่าหรือไม่
3. ทำไม `Pipeline` จึงกันข้อมูลรั่วได้ แต่การเรียก `fit_transform` เองไม่กัน
4. ข้อมูลเรียงตามคำตอบอยู่แล้ว ถ้าใช้ `KFold(n_splits=5)` แบบไม่ตั้งค่าอะไรเพิ่ม จะเกิดอะไรขึ้น
5. ใส่ `cv=5` เป็นตัวเลขธรรมดาคู่กับโมเดลแบ่งประเภท scikit-learn จะใช้วิธีแบ่งแบบใด และสับข้อมูลให้หรือไม่
6. ถ้าสรุปข้อมูล task 5 ให้เหลือ 1 แถวต่อ 1 `id` แล้ว ยังต้องใช้ `GroupKFold` อยู่หรือไม่

## ข้อควรระวัง และสรุปสำหรับอ่านทบทวน 60 วินาที

- เครื่องมือทุกตัวที่ **เรียนรู้จากข้อมูล** ได้แก่ ตัวปรับสเกล (scaler), ตัวแปลงข้อความ (vectorizer), ตัวเติมค่าว่าง (imputer), ตัวแปลงหมวดหมู่เป็นตัวเลข (encoder) ต้องสร้างจากข้อมูลฝั่งสอนเท่านั้น ถ้าใช้ `Pipeline` ปัญหานี้จะหายไปเอง
- ถ้าตัวอย่าง 1 ชิ้นมีหลายแถว ต้องจัดกลุ่มด้วยคีย์ของตัวอย่างเสมอ โจทย์ task 5 คือกรณีนี้ตรง ๆ
- ใส่ `shuffle=True, random_state=42` ให้ `KFold` และ `StratifiedKFold` เพราะทั้งสองตัวไม่สับข้อมูลให้เอง
- ตั้งค่า `scoring` ให้ตรงกับเกณฑ์ของการแข่งขัน ไฟล์เฉลยของ task 4 ใช้ `f1_macro` ไม่ใช่ accuracy
- รายงานค่าเฉลี่ยพร้อมค่าความคลาดเคลื่อนเสมอ และไม่ต้องสนใจคะแนนที่ดีขึ้นน้อยกว่าประมาณ $2\,\text{SE}$
- ข้อมูลที่เรียงตามเวลาต้องแบ่งตามลำดับเวลา ห้ามสุ่ม และควรลบแถวซ้ำออกก่อนแบ่ง
- ห้ามปรับค่าโมเดลและรายงานคะแนนจากการแบ่งชุดเดียวกัน ถ้าคะแนนที่วัดเองสูงกว่า leaderboard มาก ให้สันนิษฐานว่าข้อมูลรั่วไว้ก่อน
- จำนวนครั้งที่ต้องสอนโมเดลทั้งหมดคือ $\lvert \text{grid} \rvert \times k$ ซึ่งเป็นสูตรที่ใช้ตัดสินว่าเวลาที่มีพอหรือไม่ (ดูเพิ่มใน T19)
