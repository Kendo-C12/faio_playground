## [concept-first] ทฤษฎีก่อน แล้วดูตัวอย่าง

**คิดเลขให้เสร็จก่อนสั่งงานรัน** โจทย์ [`task6_Simple_Objects.md`](../faio-2025/qualification/task6_Simple_Objects.md) เขียนไว้ว่า "คำตอบของคุณจะถูกทดสอบกับภาพ **8000** ภาพ" และภาพแต่ละภาพมีขนาด "$2048 \times 2048$ จุดภาพ"

เมื่อรู้ตัวเลขสองตัวนี้ การคำนวณเวลาทั้งหมดก็ทำได้ทันที

- ถ้าใช้เวลาภาพละ $0.4 \text{ s/image} \times 8000 = 3200 \text{ s} = 53$ min ซึ่งคิดเป็นหนึ่งในห้าของเวลาสอบทั้งหมด
- ถ้าใช้เวลาภาพละ $1.0 \text{ s/image} \times 8000 = 8000 \text{ s} = 2$ h 13 min ซึ่งเท่ากับจบการสอบไปเลย
- ถ้าใช้เวลาภาพละ $0.1 \text{ s/image} \times 8000 = 800 \text{ s} = 13$ min ซึ่งอยู่ในระดับที่รับได้

ข้อสรุปคืองบเวลาต่อหนึ่งภาพอยู่ที่ประมาณ 0.1 ถึง 0.2 วินาที และตัวเลขนี้รู้ได้ *ก่อน* ที่จะเขียนลูปแม้แต่บรรทัดเดียว

วิธีทำจริงง่ายมาก คือจับเวลากับภาพสิบภาพ แล้วคูณด้วย 800 เพื่อให้ได้เวลาของภาพทั้ง 8000 ภาพ แล้วจึงตัดสินใจ การคำนวณครั้งเดียวนี้คือนิสัยที่มีค่าที่สุดของบทเรียนนี้

**ใช้การคำนวณทั้งก้อน ห้ามวนลูปทีละจุดภาพ** ภาพสี RGB ขนาด $2048 \times 2048$ มีตัวเลขอยู่ 12.6 ล้านค่า การใช้ลูป `for` ของ Python เดินไล่ตัวเลขเหล่านั้นใช้เวลาหลายสิบวินาที ในขณะที่การเขียนเป็นนิพจน์เดียวของ numpy ใช้เวลาเพียงหลักมิลลิวินาที

เหตุผลคือ numpy รันลูปนั้นในภาษา C บนหน่วยความจำที่วางต่อเนื่องกัน ไม่ได้รันในตัวแปลภาษา Python วิธีนี้เรียกว่า vectorisation (การเขียนคำสั่งให้ทำงานกับข้อมูลทั้งก้อนพร้อมกัน)

กฎง่าย ๆ ที่ใช้ตรวจตัวเองคือ ถ้ามีตัวแปรนับที่เดินไล่ไปทีละจุดภาพ แปลว่าแพ้ไปแล้วตั้งแต่ต้น

```python
mask = (np.abs(gray.astype(np.int16) - bg) > 20)     # ทำทั้งภาพด้วยนิพจน์เดียว
```

**อ่านภาพเป็นขาวดำเมื่อไม่ได้ใช้สี** โจทย์ข้อ 6 ต้องการเพียงแยกเส้นของรูปทรงออกจากพื้นหลัง ตัวโจทย์เขียนว่า "พื้นหลังแยกออกจากเส้นขอบของรูปทรงได้" ไม่ได้เขียนว่าสีมีความสำคัญ และยังเขียนอีกว่า "คุณเพียงต้องนับจำนวนรูปทรงเท่านั้น ไม่ต้องแยกประเภทของมัน"

การใช้ `cv2.imread(p, cv2.IMREAD_GRAYSCALE)` จะโหลดข้อมูลมาเพียงช่องสีเดียวแทนที่จะเป็นสามช่อง ผลคือใช้หน่วยความจำหนึ่งในสาม ใช้เวลาถอดรหัสภาพหนึ่งในสาม และทุกขั้นตอนหลังจากนั้นก็ถูกลงสามเท่าตามไปด้วย

**ชนิดข้อมูลคือการตัดสินใจเรื่องหน่วยความจำ** โจทย์ [`Lost_in_the_Museum.md`](../faio-2025/day2/Lost_in_the_Museum.md) ต้องการ "20,000 แถวพอดี" โดยแต่ละแถวมีค่าตัวเลข D ค่า และแนะนำให้ D เป็น 256 หรือ 512

- $20000 \times 512 \times 8$ bytes (float64) $= 82$ MB
- $20000 \times 512 \times 4$ bytes (float32) $= 41$ MB

เมื่อ float64 คือ ชนิดตัวเลขทศนิยมที่ใช้พื้นที่ 8 ไบต์ต่อค่า และ float32 คือ ชนิดที่ใช้พื้นที่ 4 ไบต์ต่อค่า

การเปลี่ยนไปใช้ float32 ลดพื้นที่ลงครึ่งหนึ่ง และการคำนวณ cosine similarity ก็ไม่ได้แย่ลงเลยที่ความละเอียดระดับนี้

ส่วนตัวภาพ 20,000 ภาพนั้น ต่อให้ย่อเหลือ $224 \times 224 \times 3$ และเก็บเป็น uint8 (ชนิดจำนวนเต็มที่ใช้พื้นที่ 1 ไบต์ เก็บค่า 0 ถึง 255) ก็ยังกินพื้นที่ถึง 3 GB ถ้าถือไว้ทั้งหมดพร้อมกัน ข้อสรุปคือไม่ถือภาพไว้ ให้ถือเฉพาะ embedding เท่านั้น

มีกับดักที่พบบ่อยอีกข้อหนึ่ง คือจุดภาพชนิด uint8 จะกลายเป็น float64 ทันทีที่หารด้วย 255 โดยไม่ระวัง วิธีเขียนที่ถูกต้องคือ `img.astype(np.float32) / 255`

**ทำทีละชุด แล้วคืนหน่วยความจำ** ไฟล์ตัวอย่างของผู้จัดใน [`host-author-s-baseline.ipynb`](../faio-2025/day1/host-author-s-baseline.ipynb) ทำเรื่องนี้อย่างชัดเจน มันนิยามฟังก์ชัน `memory_usage_gb()` บนค่า `psutil.Process(os.getpid()).memory_info().rss` แล้วพิมพ์ปริมาณหน่วยความจำที่ใช้หลังโหลดไฟล์ JSON แต่ละไฟล์ จากนั้นแปลงข้อมูลที่คลี่แล้วเป็นตาราง แล้วสั่ง `del players, teams, league; gc.collect()` เพื่อคืนหน่วยความจำ

ภายในลูปที่เรียกโมเดลภาษา มันก็สั่ง `del inputs, generation; torch.cuda.empty_cache(); gc.collect()` ทุกรอบเช่นกัน รูปแบบการทำงานคือ ประมวลผลข้อมูลหนึ่งชุด เขียนผลลัพธ์ออกไป แล้วคืนหน่วยความจำของชุดนั้น

ผลตอบแทนของวินัยนี้จับต้องได้ การกรองด้วยคำนำหน้าในไฟล์ตัวอย่างลดข้อมูลผู้เล่น "จาก 35 ล้านแถว เหลือ 3.8 ล้านแถว" ซึ่งเป็นการแก้ปัญหาหน่วยความจำพอ ๆ กับที่เป็นการแก้ปัญหาความแม่นยำ

**หลีกเลี่ยง `DataFrame.apply` ในส่วนที่ทำงานหนัก** คำสั่ง `df.apply(f, axis=1)` คือลูปของ Python ที่มีค่าใช้จ่ายของ DataFrame พ่วงมาในทุกแถว วิธีที่ควรใช้แทนคือคำสั่งจัดการข้อความแบบทั้งคอลัมน์ เช่น `df.paths.str.split(".").str[0]` หรือทำงานกับอาร์เรย์ numpy ที่อยู่ข้างใต้โดยตรง

ไฟล์ตัวอย่างของผู้จัดใช้ `.str.endswith` และ `.str.startswith` ในการกรองเส้นทางด้วยเหตุผลนี้เอง เพราะคำสั่งเหล่านั้นรันในภาษา C แต่ในอีกจุดหนึ่งมันกลับใช้ `.apply(lambda x: x.split(".")[0])` ซึ่งเป็นการเขียนสิ่งเดียวกันในแบบที่ช้ากว่า

**วัดก่อน แล้วค่อยปรับ** เครื่องมือที่ใช้ได้ทันทีมีสามอย่าง คือใส่ `%%time` ไว้หัวเซลล์ ใส่ `tqdm` ครอบลูปเพื่อให้เห็นอัตราความเร็วจริงและคำนวณเวลาที่เหลือได้ และใช้ `time.perf_counter()` คร่อมฟังก์ชันที่สงสัย

การปรับปรุงโปรแกรมที่ยังไม่เคยจับเวลาเลย คือการปรับปรุงบรรทัดที่ผิดบรรทัด

**ห้ามขยาย DataFrame ภายในลูป** คำสั่ง `bm25_df = pd.concat([bm25_df, temp_df])` ที่อยู่ในลูป 220 รอบ แบบที่ไฟล์ตัวอย่างของผู้จัดทำไว้ จะคัดลอกข้อมูลทั้งหมดใหม่ทุกรอบ ทำให้ต้นทุนเพิ่มขึ้นแบบกำลังสองของจำนวนรอบ วิธีที่ถูกต้องคือเก็บผลลัพธ์ใส่ list ไปก่อน แล้วเรียก `pd.concat` เพียงครั้งเดียวตอนจบ

## [code-first] โค้ดที่รันได้ พร้อมคำอธิบายในคอมเมนต์

```python
import time, gc, os, numpy as np, pandas as pd, cv2, psutil
from tqdm.auto import tqdm

mem_gb = lambda: psutil.Process(os.getpid()).memory_info().rss / 1024**3

def count_figures(path):
    # ภาพขาวดำ: 1 ช่องสีแทนที่จะเป็น 3 ช่อง เหลือทั้งเวลาถอดรหัสและขนาดข้อมูลเพียงหนึ่งในสาม
    g = cv2.imread(str(path), cv2.IMREAD_GRAYSCALE)
    bg = np.bincount(g.ravel()).argmax()                  # ค่าที่พบมากที่สุดคือพื้นหลัง
    # คำนวณทั้งก้อนกับจุดภาพ 4.2 ล้านจุด ใช้ int16 กันค่าวนกลับของ uint8 โดยไม่ต้องไปถึง float64
    mask = (np.abs(g.astype(np.int16) - int(bg)) > 20).astype(np.uint8)
    cnts, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    return sum(1 for c in cnts if cv2.contourArea(c) >= 20)

# 1. วัดเวลาก่อนเป็นอันดับแรก ด้วยข้อมูล 10 ชิ้น แล้วคำนวณออกไปถึงงานทั้งชุด
files = sorted(os.listdir("test_images"))
t = time.perf_counter()
for p in files[:10]:
    count_figures(os.path.join("test_images", p))
per = (time.perf_counter() - t) / 10
print(f"{per:.3f} s/image -> {per*len(files)/60:.1f} min for {len(files)} images")
# 0.4 วินาทีต่อภาพ คูณ 8000 ภาพ เท่ากับ 53 นาที ถ้าตัวเลขนี้รับไม่ได้ ต้องแก้เดี๋ยวนี้

# 2. รันเป็นชุด ทยอยเขียนผลลัพธ์ลงไฟล์ และคืนหน่วยความจำ tqdm จะแสดงอัตราความเร็วจริง
rows, FLUSH = [], 500
for i, p in enumerate(tqdm(files)):
    rows.append((i, count_figures(os.path.join("test_images", p))))
    if (i + 1) % FLUSH == 0:                      # กันโปรแกรมล่ม: มีไฟล์บางส่วนอยู่บนดิสก์แล้ว
        pd.DataFrame(rows, columns=["id", "count"]).to_csv("submit.csv", index=False)
        gc.collect()
        tqdm.write(f"{i+1} done, RAM {mem_gb():.2f} GB")
pd.DataFrame(rows, columns=["id", "count"]).to_csv("submit.csv", index=False)

# 3. embedding: จองพื้นที่ float32 ไว้ล่วงหน้า ห้ามเก็บใส่ list แล้วค่อยต่อกัน (จะกินพื้นที่สูงสุดสองเท่า)
D, N, B = 512, 20000, 128
emb = np.empty((N, D), np.float32)
for s in range(0, N, B):
    emb[s:s+B] = model.encode(names[s:s+B], batch_size=B).astype(np.float32)
emb /= np.linalg.norm(emb, axis=1, keepdims=True)      # ทำ L2 ครั้งเดียวตอนจบ
```
