ระดับความรู้ 0 · **โอกาสออกสอบ อันดับ 2** · ประมาณ 50 นาที

**Frequency (ความถี่)** คือ จำนวนรอบที่คลื่นสั่นครบในหนึ่งวินาที มีหน่วยเป็น Hz เสียงที่สูงคือเสียงที่มีความถี่มาก และเสียงที่ต่ำคือเสียงที่มีความถี่น้อย

**FFT (วิธีแยกสัญญาณออกเป็นคลื่นความถี่ต่าง ๆ)** คือ ขั้นตอนวิธีที่รับสัญญาณเข้าไปแล้วบอกว่าสัญญาณนั้นประกอบด้วยคลื่นความถี่ใดบ้าง และแต่ละความถี่มีพลังงานมากน้อยเพียงใด ชื่อเต็มคือ Fast Fourier Transform

**Harmonics (คลื่นที่มีความถี่เป็นจำนวนเท่าของความถี่หลัก)** คือ คลื่นที่เกิดพร้อมกับเสียงหลักเสมอ โดยมีความถี่เป็น 2 เท่า 3 เท่า 4 เท่า ของความถี่หลัก

หัวข้อนี้ยากที่สุดในวันที่ 4 และเป็นหัวใจของโจทย์ `Missing_Fundamental_Puzzle` ซึ่งลบความถี่หลักออกจากไฟล์เสียงไปแล้ว แต่ยังบังคับให้ทายระดับเสียงให้ถูก

**เปรียบเทียบให้เห็นภาพแบบง่ายที่สุด** เวลาดีดสายกีตาร์หนึ่งสาย เราไม่ได้ยินคลื่นเดียว แต่ได้ยินคลื่นหลักหนึ่งคลื่น บวกกับคลื่นบาง ๆ อีกชุดหนึ่งที่มีความถี่เป็น 2 เท่า 3 เท่า 4 เท่า ของคลื่นหลักซ้อนอยู่ด้วย สมมติคลื่นหลักคือ 220 Hz ชุดคลื่นที่ได้ยินจริงคือ 220, 440, 660, 880, 1100 Hz เรียงกันเป็นระยะเท่า ๆ กัน ทีนี้ถ้ามีคนลบคลื่น 220 Hz ทิ้งไป เหลือเพียง 440, 660, 880, 1100 Hz หูของคนก็ยังได้ยินเป็นโน้ตตัวเดิมอยู่ดี เพราะ *ระยะห่าง* ระหว่างคลื่นที่เหลือยังเท่ากับ 220 Hz อยู่ทุกช่วง ระยะห่างนั้นเองที่บอกความถี่หลัก นี่คือแนวคิดเรื่อง missing fundamental ทั้งหมด และเป็นกุญแจของโจทย์ข้อนี้

## [concept-first] ทฤษฎีก่อน แล้วดูตัวอย่าง

### อัตราการสุ่มตัวอย่าง และขีดจำกัดของ Nyquist

**Sampling rate (จำนวนครั้งที่วัดสัญญาณต่อวินาที)** เขียนแทนด้วย $f_s$ สัญญาณดิจิทัลคือค่าความสูงของคลื่นที่ถูกวัดไว้ $f_s$ ครั้งต่อวินาที

**ขีดจำกัด Nyquist–Shannon** บอกว่าสัญญาณที่ถูกวัดเป็นช่วง ๆ แบบนี้ แทนความถี่ได้เฉพาะที่ต่ำกว่าค่าต่อไปนี้เท่านั้น

$$
f_{\text{Nyq}} = \frac{f_s}{2}
$$

เมื่อ $f_{\text{Nyq}}$ คือ ความถี่สูงสุดที่สัญญาณนั้นแทนได้ และ $f_s$ คือ อัตราการสุ่มตัวอย่าง

ความถี่ที่สูงกว่านั้นจะพับกลับลงมา เรียกว่า aliasing (การปลอมตัวเป็นความถี่ต่ำ) และหลอกเราว่าเป็นความถี่ที่ต่ำกว่าความจริง ในโจทย์ `Missing_Fundamental_Puzzle` ค่า $f_s = 22050$ Hz ช่วงที่ใช้งานได้จริงจึงเป็น **0 ถึง 11025 Hz** ส่วนเซ็นเซอร์ของโจทย์ task 5 ที่ 200 Hz ให้ช่วง 0 ถึง 100 Hz ซึ่งเพียงพอมากสำหรับการเคลื่อนไหวของคน

### ตัว FFT เอง

คำสั่ง `np.fft.rfft(x)` แยกข้อมูล $N$ ตัว ออกเป็นสัมประสิทธิ์เชิงซ้อนหนึ่งตัวต่อหนึ่งช่องความถี่

$$
X_k = \sum_{n=0}^{N-1} x_n \, e^{-2\pi i k n / N}
$$

เมื่อ $X_k$ คือ สัมประสิทธิ์ของช่องความถี่ที่ $k$, $x_n$ คือ ค่าที่วัดได้ลำดับที่ $n$ และ $N$ คือ จำนวนค่าที่นำมาคำนวณ

คำสั่ง `rfft` คืนเฉพาะช่องความถี่ที่ไม่เป็นลบ ซึ่งมีจำนวน $N/2 + 1$ ช่อง และเท่านี้ก็ครบทุกอย่างที่สัญญาณจำนวนจริงมี จากนั้นใช้ `np.abs(...)` เพื่อให้ได้ **magnitude spectrum (สเปกตรัมขนาด — แผนภาพที่บอกว่าแต่ละความถี่มีพลังงานเท่าไร)** ส่วนข้อมูลเรื่องเฟส (phase — ตำแหน่งเริ่มต้นของคลื่น) จะถูกทิ้งไป และแทบไม่มีผลกับการหาระดับเสียง

### ช่องความถี่ และความละเอียด

ช่องที่ $k$ ของ FFT ที่ใช้ข้อมูล $N$ ตัว อยู่ที่ความถี่

$$
f_k = \frac{k f_s}{N}
$$

ดังนั้นระยะห่างระหว่างช่อง ซึ่งก็คือความละเอียดเชิงความถี่ คือ

$$
\Delta f = \frac{f_s}{N}
$$

เมื่อ $\Delta f$ คือ ความกว้างของหนึ่งช่องความถี่ หน่วยเป็น Hz

ที่ $f_s = 22050$ และ $N = 2048$ จะได้ 10.8 Hz ตัวเลขนี้ตัดสินว่าเรามองเห็นอะไรได้บ้าง เช่น harmonics สองตัวที่ห่างกัน 30 Hz แยกออกจากกันได้ แต่โน้ตต่ำที่มีระยะห่าง 20 Hz แยกไม่ออก กฎที่ต้องจำคือ หน้าต่างข้อมูลที่ยาวกว่าให้ความละเอียดเชิงความถี่ที่ดีกว่า แต่ให้ความละเอียดเชิงเวลาที่แย่กว่า และการแลกนี้หลีกเลี่ยงไม่ได้ ใช้ `np.fft.rfftfreq(N, 1/fs)` เพื่อให้ได้ความถี่ของแต่ละช่อง และห้ามคำนวณดัชนีช่องด้วยมือเอง

### การคูณหน้าต่างก่อนทำ FFT

FFT ตั้งสมมติฐานว่าข้อมูล $N$ ตัวที่ให้ไปนั้นวนซ้ำต่อกันเป็นคาบไปเรื่อย ๆ ถ้ารูปคลื่นตรงหัวกับตรงท้ายต่อกันไม่สนิท จะเกิดรอยต่อที่กระโดด และพลังงานจากรอยกระโดดนั้นจะกระจายเลอะไปทั่วทุกช่องความถี่ อาการนี้เรียกว่า spectral leakage (พลังงานรั่วไปเปื้อนช่องความถี่อื่น) ซึ่งกลบ harmonics ที่มีพลังงานน้อยจนหาไม่เจอ

วิธีแก้คือคูณข้อมูลด้วยหน้าต่างที่ค่อย ๆ ลดลงที่ปลายทั้งสองข้างก่อน เช่น `x * np.hanning(N)` ซึ่งบังคับให้ค่าที่ปลายทั้งสองข้างเป็นศูนย์ ให้ทำขั้นตอนนี้ก่อนทำ FFT กับเสียงจริงทุกครั้ง

### Spectrogram และ log-mel

**Spectrogram** คือ การหั่นสัญญาณออกเป็นหน้าต่างสั้น ๆ ที่ซ้อนเหลื่อมกัน แล้วเอาสเปกตรัมขนาดของแต่ละหน้าต่างมาเรียงต่อกัน ผลลัพธ์เป็นภาพสองมิติที่แกนหนึ่งเป็นเวลาและอีกแกนเป็นความถี่

**Mel spectrogram** คือ spectrogram ที่จัดแกนความถี่ใหม่ตามสเกล mel ซึ่งเป็นสเกลที่ใกล้เคียงลอการิทึม คือ ละเอียดในย่านต่ำและหยาบในย่านสูง ตรงกับลักษณะการได้ยินของคน และช่วยบีบจาก 1025 ช่องให้เหลือประมาณ 128 ช่อง การใส่ `log` กับค่าขนาดจะบีบช่วงของตัวเลขให้แคบลง ทำให้ harmonics ที่เบามองเห็นได้ ผลลัพธ์คืออาร์เรย์สองมิติ ซึ่งจะป้อนเข้า CNN ในบท T30 ก็ได้ หรือจะสรุปแต่ละแถวเป็นค่าเฉลี่ยกับส่วนเบี่ยงเบนเพื่อป้อนโมเดลแบบตารางก็ได้

### Harmonics และความถี่หลัก

โน้ตที่เล่นออกมาโดยมีความถี่หลัก $f_0$ จะสร้างพลังงานที่ความถี่ซึ่งเป็นจำนวนเต็มเท่าของมัน

$$
f_k = k f_0, \qquad k = 1, 2, 3, \ldots
$$

เมื่อ $f_0$ คือ ความถี่หลัก และ $f_k$ คือ ความถี่ของ harmonic ลำดับที่ $k$

ระดับเสียงที่คนได้ยินคือ $f_0$ และข้อเท็จจริงเชิงโครงสร้างที่สำคัญที่สุดคือ **ระยะห่าง** ระหว่าง harmonics ที่อยู่ติดกันก็เท่ากับ $f_0$ เช่นกัน พูดอีกอย่างคือ $f_0$ ถูกเข้ารหัสไว้ถึงสองที่ ที่แรกคือยอดคลื่นที่ต่ำที่สุด และที่สองคือระยะห่างที่เท่ากันของยอดคลื่นทุกยอดที่อยู่เหนือขึ้นไป

### หมายเลขโน้ตแบบ MIDI

คำตอบของโจทย์เป็นจำนวนเต็ม โดยกำหนดให้ 69 คือโน้ต A4 ซึ่งมีความถี่ 440 Hz และหนึ่งช่วงคู่แปดแบ่งเป็น 12 ครึ่งเสียง

$$
f = 440 \cdot 2^{(n - 69)/12}
$$

$$
n = 69 + 12 \log_2\!\left(\frac{f}{440}\right)
$$

เมื่อ $f$ คือ ความถี่หน่วย Hz และ $n$ คือ หมายเลขโน้ตแบบ MIDI

ตัวอย่างเช่น $n = 60$ ซึ่งคือโน้ต C4 เท่ากับ $440 \cdot 2^{-9/12} \approx 261.6$ Hz และหนึ่งครึ่งเสียงคืออัตราส่วน $2^{1/12} \approx 1.0595$ ซึ่งต่างกันเพียงประมาณ 6 เปอร์เซ็นต์เท่านั้น เมื่อโจทย์มี 61 ประเภทกินช่วงประมาณห้าคู่แปด ค่า $f_0$ ที่ประมาณได้จึงต้องแม่นในระดับไม่กี่เปอร์เซ็นต์ และวิธีที่ปลอดภัยกว่ามากคือประมาณ $f_0$ ให้ได้ก่อน แล้วแปลงด้วยสูตร แล้วปัดเป็นจำนวนเต็ม $n$ ที่ใกล้ที่สุด แทนที่จะให้โมเดลแบ่งประเภทเรียนคำตอบ 61 แบบที่ไม่มีลำดับจากศูนย์

## [problem-first] เริ่มจากโจทย์จริง แล้วหาว่าต้องรู้อะไร

เปิดไฟล์ [`Missing_Fundamental_Puzzle.md`](../faio-2025/day1/Missing_Fundamental_Puzzle.md) ข้อมูลคือไฟล์เสียง WAV แบบช่องเดียว 16 บิต ที่ 22050 Hz ยาว 1 ถึง 4 วินาที มีคำตอบ 61 ประเภทตามหมายเลขโน้ต MIDI ที่ปรากฏในข้อมูล ไฟล์ที่ต้องส่งมีคอลัมน์ `Path, Pitch_ID` วัดผลด้วยความแม่นยำธรรมดา และชุดข้อมูลเป็นรุ่นดัดแปลงของ TinySOL

จากนั้นอ่านประโยคที่เป็นตัวโจทย์ทั้งหมด "The audio has been preprocessed and **some of the frequencies have been removed from the signal**" คือเสียงถูกแปลงมาก่อนแล้ว และบางความถี่ถูกลบออกจากสัญญาณ และอีกประโยคหนึ่งบอกว่าโมเดล "must infer pitch from the spectral and temporal structure of the remaining harmonics, **without access to the fundamental frequency**" คือ ต้องอนุมานระดับเสียงจากโครงสร้างของ harmonics ที่เหลืออยู่ โดยไม่มีความถี่หลักให้ดู

ผลที่ตามมามีดังนี้

1. **วิธีประมาณระดับเสียงแบบตรงไปตรงมาจะผิดเสมอ** วิธีที่ว่าคือ "หยิบยอดคลื่นที่ต่ำที่สุดหรือสูงที่สุด" ซึ่งจะคืนค่า $2f_0$ หรือ $3f_0$ เพราะตัว $f_0$ ถูกลบไปแล้ว ผลคือตอบสูงเกินไปหนึ่งคู่แปดหรือหนึ่งคู่ห้า และผิดแบบ *เป็นระบบ* กับทุกไฟล์ ความผิดพลาดแบบนี้ไม่ใช่สัญญาณรบกวนที่เฉลี่ยแล้วหายไป
2. **แต่ harmonics ที่เหลือยังห่างกันเท่ากับ $f_0$ อยู่** สเปกตรัมมีหน้าตาเหมือนซี่หวี โดยมีซี่อยู่ที่ $2f_0, 3f_0, 4f_0, \ldots$ และช่องว่างระหว่างซี่ที่อยู่ติดกันคือ $f_0$ การกู้ **ระยะห่าง** กลับมาได้ก็คือการกู้ระดับเสียงกลับมาได้ นี่คือเหตุผลเดียวกับที่คนยังได้ยินเป็นโน้ต C4 แม้ส่วนประกอบที่เป็น C4 จะถูกลบไปแล้ว ซึ่งเป็นปรากฏการณ์ทางการได้ยินที่โจทย์ข้อนี้ใช้ตั้งชื่อ
3. **มีสามวิธีวัดระยะห่างนั้น** เรียงจากทนทานน้อยไปมาก วิธีแรกคือหาผลต่างระหว่างความถี่ของยอดคลื่นที่ตรวจพบ วิธีที่สองคือ **autocorrelation ของสเปกตรัมขนาด (การหาว่าสเปกตรัมเลื่อนไปเท่าไรแล้วยังทับกับตัวเองได้ดีที่สุด)** ซึ่งระยะเลื่อนแรกที่ให้ค่าสูงคือ $f_0$ ในหน่วย Hz และวิธีที่สามคือ **cepstrum (ผลของการทำ FFT ย้อนกลับกับลอการิทึมของสเปกตรัมขนาด)** ซึ่งตำแหน่งยอดของมันคือคาบเวลา $1/f_0$ ในหน่วยวินาที วิธีที่ควรเขียนก่อนคือ autocorrelation ของสเปกตรัม
4. **แปลง $f_0$ ที่ประมาณได้เป็นหมายเลข MIDI** ด้วยสูตร $69 + 12\log_2(f/440)$ แล้วปัดเป็นจำนวนเต็ม แล้วจับคู่กับรหัสคำตอบที่ให้ไว้ใน `train.csv` จากนั้น เนื่องจากมีไฟล์ฝึกที่รู้คำตอบอยู่ 2,330 ไฟล์ ให้วัดว่าตอบถูกเป๊ะบ่อยแค่ไหน และตอบเพี้ยนไปพอดี 12 หรือ 19 ครึ่งเสียงบ่อยแค่ไหน ความผิดสองแบบนี้เป็นตัวบ่งชี้โรคได้ทันที คือ ผิด $+12$ แปลว่าไปจับ $2f_0$ ซึ่งห่างกันหนึ่งคู่แปดพอดี และผิด $+19$ แปลว่าไปจับ $3f_0$ ซึ่งคือหนึ่งคู่แปดบวกหนึ่งคู่ห้า เพราะ $12\log_2(3) \approx 19.02$
5. **CNN ที่ทำงานบน log-mel spectrogram ก็ใช้ได้** และจะเรียนรูปแบบซี่หวีได้เอง โดยมี 61 ประเภทและไฟล์ฝึก 2,330 ไฟล์ ให้ใช้เป็นโมเดลตัวที่สอง และผสมผลกันเฉพาะเมื่อวิธีคำนวณตรง ๆ ให้คำตอบไม่ตรงกับ CNN บ่อยครั้ง

## [code-first] โค้ดที่รันได้ พร้อมคำอธิบายในคอมเมนต์

```python
import numpy as np
import scipy.io.wavfile as wav

fs, x = wav.read("note.wav")                # fs = 22050 ดังนั้นขีดจำกัด Nyquist = 11025 Hz
x = x.astype(np.float32) / 32768.0          # แปลงค่าจาก 16 บิต ให้อยู่ในช่วง [-1, 1]

N = 8192                                    # ความละเอียด = fs/N = 2.7 Hz ใช้หน้าต่างยาวเพื่อให้ระดับเสียงละเอียด
seg = x[:N] * np.hanning(N)                 # เสียง 1-4 วินาทีที่ 22050 Hz มีจำนวนค่ามากกว่า N เสมอ
                                            # ต้องคูณหน้าต่างก่อน ไม่อย่างนั้นพลังงานที่รั่วจะกลบ harmonics ที่เบา
S = np.abs(np.fft.rfft(seg, N))             # สเปกตรัมขนาด มีจำนวนช่อง N//2 + 1
freqs = np.fft.rfftfreq(N, 1 / fs)          # ห้ามคำนวณดัชนีช่องความถี่ด้วยมือเอง

# วิธีที่ผิดสำหรับโจทย์ข้อนี้: ยอดคลื่นที่สูงที่สุดคือ 2*f0 หรือ 3*f0 เพราะ f0 ถูกลบไปแล้ว
naive_f0 = freqs[S.argmax()]

# วิธีที่ถูก: harmonics ที่เหลือยังห่างกันเท่ากับ f0 อยู่
# จึงหา autocorrelation ของสเปกตรัม แล้วอ่านค่าระยะเลื่อนออกมา
A = np.correlate(S - S.mean(), S - S.mean(), mode="full")[len(S) - 1:]
df = freqs[1] - freqs[0]                    # ความกว้างของหนึ่งช่อง หน่วย Hz เท่ากับ fs/N
lo, hi = int(50 / df), int(2000 / df)       # ค้นในช่วง 50-2000 Hz ซึ่งเป็นช่วงที่ f0 เป็นไปได้
f0 = (lo + int(np.argmax(A[lo:hi]))) * df   # ระยะเลื่อนแรกที่ให้ค่าสูง = ระยะห่าง harmonic = f0

def to_midi(f):                             # 69 = A4 = 440 Hz และหนึ่งคู่แปดมี 12 ครึ่งเสียง
    return int(round(69 + 12 * np.log2(f / 440.0)))

print("naive", to_midi(naive_f0), "| spacing", to_midi(f0))
# ผิด +12 แปลว่าไปจับ 2*f0 ส่วนผิด +19 แปลว่าไปจับ 3*f0 ให้ตรวจรูปแบบนี้กับ train.csv
# โมเดลตัวที่สอง: ใช้ log-mel spectrogram เป็นข้อมูลเข้าแบบสองมิติของ CNN (ดู T30)

```
