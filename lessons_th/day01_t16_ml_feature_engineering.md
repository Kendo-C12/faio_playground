ระดับความรู้ 1 · **โอกาสออกสอบ อันดับ 1** · ประมาณ 50 นาที

**Feature (คุณลักษณะ)** คือ ตัวเลขหนึ่งตัวที่โมเดล (model — โปรแกรมที่เรียนรู้จากข้อมูล) นำไปใช้ทำนายได้ ข้อมูลดิบหนึ่งชุดสามารถแปลงออกมาเป็นคุณลักษณะได้หลายสิบตัว

**Feature engineering (การสร้างคุณลักษณะ)** คือ การตัดสินใจว่าจะคำนวณตัวเลขอะไรบ้างจากข้อมูลดิบ เพื่อให้โมเดลมีข้อมูลที่ใช้งานได้จริง

ในการสอบที่มีเวลา 4 ชั่วโมง งานส่วนนี้มักให้คะแนนเพิ่มมากกว่าการเปลี่ยนไปใช้โมเดลที่ซับซ้อนขึ้น เพราะโมเดลที่ดีที่สุดก็ทำอะไรไม่ได้ถ้าตัวเลขที่ป้อนเข้าไปไม่มีข้อมูลที่เป็นประโยชน์อยู่เลย

## [concept-first] ทฤษฎีก่อน แล้วดูตัวอย่าง

งานในหัวข้อนี้แบ่งได้เป็นสามอย่างหลัก บวกกับขั้นตอนคัดเลือกอีกหนึ่งขั้น

- **สร้าง (Build)** คือ การเปลี่ยนโครงสร้างของข้อมูลดิบให้กลายเป็นตัวเลข เช่น สรุปข้อมูลหลายแถวให้เหลือค่าสถิติต่อหนึ่งตัวอย่าง นำสองคอลัมน์มาหารกันเพื่อได้อัตราส่วน หรือดึงชั่วโมงของวันออกมาจากเวลาที่บันทึกไว้ ไฟล์ `qaz_letters.md` เป็นตัวอย่างของการทำสิ่งนี้กับรูปภาพ โดยระบุคุณลักษณะไว้ครบ ได้แก่ ค่าเฉลี่ยความเข้ม ส่วนเบี่ยงเบนมาตรฐาน (standard deviation — ตัวเลขบอกการกระจายของข้อมูล) ค่าต่ำสุดและสูงสุด ความเบ้ (skewness) ความโด่ง (kurtosis) ฮิสโทแกรม 16 ช่อง Hu moments ระยะเชิงรัศมี Fourier descriptors การฉายภาพ การแบ่งโซน DCT และ wavelets ให้อ่านรายการนี้เหมือนเมนูอาหาร เพราะเป็นการที่กรรมการบอกเองว่าคุณลักษณะแบบใดบ้างที่ถือว่าใช้ได้

- **ปรับสเกล (Scale)** คือ การทำให้ทุกคอลัมน์มีขนาดตัวเลขใกล้เคียงกัน เครื่องมือหลักมีสองตัว คือ `StandardScaler` ที่ปรับให้ค่าเฉลี่ยเป็น 0 และส่วนเบี่ยงเบนมาตรฐานเป็น 1 กับ `MinMaxScaler` ที่บีบค่าให้อยู่ในช่วง $[0, 1]$ โมเดลที่ต้องใช้การปรับสเกลคือโมเดลที่คำนวณระยะทางหรือใช้ความชัน ได้แก่ kNN, SVM, logistic regression, k-means และ PCA ส่วนโมเดลกลุ่มต้นไม้ (tree) และ boosting **ไม่** ต้องการเลย เพราะมันเพียงเปรียบเทียบค่ากับเกณฑ์เท่านั้น สรุปคือ การปรับสเกลขึ้นอยู่กับชนิดของโมเดล ไม่ได้ขึ้นอยู่กับข้อมูล

- **แปลงหมวดหมู่เป็นตัวเลข (Encode)** คือ การเปลี่ยนข้อความที่เป็นชื่อหมวดให้เป็นตัวเลขที่โมเดลอ่านได้ ใช้ **one-hot** (การสร้างคอลัมน์ใหม่หนึ่งคอลัมน์ต่อหนึ่งหมวด ค่าเป็น 0 หรือ 1) เมื่อหมวดไม่มีลำดับและมีจำนวนน้อย และใช้ **ordinal** (การแทนหมวดด้วยเลข 0, 1, 2 ตามลำดับ) เฉพาะเมื่อลำดับนั้นมีความหมายจริง ๆ คอลัมน์คำตอบอย่าง `ru`/`kaz`/`eng` คือเป้าหมายที่ต้องทำนาย ไม่ใช่คุณลักษณะ จึงห้ามนำไปแปลงแล้วใส่กลับเข้าไปใน X

- **คัดเลือก (Selection)** คือ การตัดคอลัมน์ที่ไม่มีประโยชน์ทิ้ง เริ่มจากตัดคอลัมน์ที่มีค่าเดียวทั้งคอลัมน์ (`df.nunique() == 1`) แล้วตัดคอลัมน์ที่แทบซ้ำกัน (คือคู่ที่มีค่าสหสัมพันธ์ $|\text{corr}| > 0.98$ โดย correlation คือ ตัวเลขระหว่าง -1 ถึง 1 ที่บอกว่าสองคอลัมน์เคลื่อนไหวตามกันแค่ไหน) จากนั้นจึงจัดอันดับคอลัมน์ที่เหลือด้วยค่าความสำคัญที่โมเดลให้มา เมื่อข้อมูลสอนมีน้อย คุณลักษณะจำนวนน้อยแต่ดีจะชนะคุณลักษณะจำนวนมากเสมอ

ตัวอย่างที่เห็นภาพชัด คือ คุณลักษณะที่สร้างขึ้นเองแล้วดีกว่าคอลัมน์ดิบทุกตัว สำหรับข้อมูลจากเซ็นเซอร์ IMU (เซ็นเซอร์วัดความเร่งและการหมุนที่ติดกับตัวคน) ให้คำนวณ **ขนาดของความเร่ง (magnitude)** ดังนี้

$$
\text{amag} = \sqrt{a_x^2 + a_y^2 + a_z^2}
$$

เมื่อ $a_x$, $a_y$, $a_z$ คือ ค่าความเร่งในแกน x, y และ z ตามลำดับ และ $\text{amag}$ คือ ขนาดรวมของความเร่งโดยไม่สนใจทิศทาง

ค่านี้ไม่เปลี่ยนแปลงตามมุมที่ติดเซ็นเซอร์ไว้บนตัว ถ้าดู `ax` เพียงตัวเดียวค่าจะขึ้นกับว่าเซ็นเซอร์ถูกหันไปทางไหน แต่ `amag` ไม่ขึ้นกับสิ่งนั้น เขียนเพิ่มเพียงบรรทัดเดียว แต่กำจัดตัวแปรกวนที่คอลัมน์ดิบแก้ไม่ได้ออกไปได้เลย

## [problem-first] เริ่มจากโจทย์จริง แล้วหาว่าต้องรู้อะไร

เปิดไฟล์ [`task5_Can_You_Become_AI_Yoga_Instructor.md`](../faio-2025/qualification/task5_Can_You_Become_AI_Yoga_Instructor.md) โจทย์นี้ให้สัญญาณดิบมา 6 ตัวและคำตอบแบบสองทางเลือก โดยไม่ได้ให้รายการคุณลักษณะมาด้วย ซึ่งต่างจาก `qaz_letters.md` ที่คำนวณคุณลักษณะมาให้เสร็จแล้ว

โจทย์นี้บังคับให้ต้องคิดคุณลักษณะขึ้นเองในสี่เรื่องต่อไปนี้

1. คำตอบผูกกับการทำท่า 1 ครั้ง แต่สัญญาณถูกบันทึกทีละช่วงเวลา ดังนั้นคุณลักษณะทุกตัวต้องเป็น **ค่าสรุปรวมของการทำท่าครั้งนั้นทั้งครั้ง**
2. คำถามคือท่าถูกหรือผิด ซึ่งเป็นเรื่องของรูปแบบการเคลื่อนไหว ไม่ใช่ระดับเฉลี่ยของค่า ดังนั้นคุณลักษณะที่วัดการกระจาย เช่น `std`, $\max - \min$ และ RMS จะมีข้อมูลมากกว่าค่า `mean`
3. เซ็นเซอร์มี 3 แกนต่อชนิด และมุมที่ติดตั้งไม่แน่นอน จึงควรสร้างคุณลักษณะที่ทนต่อการหมุน ได้แก่ ขนาดรวม (magnitude) และค่าสหสัมพันธ์ระหว่างแกน
4. ไม่มีข้อความใดบอกว่าแต่ละช่วงยาวเท่ากัน จึงควรใส่ `n_rows` คือจำนวนแถวของแต่ละกลุ่มเป็นคุณลักษณะด้วย เพราะระยะเวลาที่ใช้ทำท่าเองก็อาจแยกคำตอบสองแบบออกจากกันได้

เปรียบเทียบกับ [`qaz_letters.md`](../faio-2025/day1/qaz_letters.md) ในโจทย์นั้นกรรมการทำงานส่วนนี้ให้เสร็จแล้ว งานที่เหลือจึงเป็นการเลือกโมเดลล้วน ๆ การแยกให้ออกภายในห้านาทีแรกว่ากำลังเจอสถานการณ์แบบใดในสองแบบนี้ คือสิ่งที่กำหนดว่าจะใช้เวลาทั้งรอบไปกับอะไร

## [code-first] โค้ดที่รันได้ พร้อมคำอธิบายในคอมเมนต์

```python
import numpy as np
import pandas as pd

SIG = ["ax", "ay", "az", "wx", "wy", "wz"]

def featurise(X):
    X = X.copy()
    # ขนาดรวมที่ทนต่อการหมุนของเซ็นเซอร์ ดีกว่าการใช้แกนดิบแกนใดแกนหนึ่ง
    X["amag"] = np.sqrt(X.ax**2 + X.ay**2 + X.az**2)
    X["wmag"] = np.sqrt(X.wx**2 + X.wy**2 + X.wz**2)
    cols = SIG + ["amag", "wmag"]

    # การกระจายสำคัญกว่าระดับเฉลี่ย เมื่อคำถามคือ "เคลื่อนไหวถูกต้องหรือไม่"
    agg = X.groupby("id")[cols].agg(
        ["mean", "std", "min", "max", "median",
         lambda s: np.sqrt((s ** 2).mean()),        # RMS หรือค่าพลังงานของสัญญาณ
         lambda s: s.max() - s.min()]               # พิสัย คือค่าสูงสุดลบค่าต่ำสุด
    )
    agg.columns = ["_".join(map(str, c)) for c in agg.columns]

    agg["n_rows"] = X.groupby("id").size()          # ใช้ระยะเวลาเป็นคุณลักษณะ
    # ค่าสหสัมพันธ์ข้ามแกน บอกว่าเคลื่อนไหวประสานกันหรือกระจัดกระจาย
    for a, b in [("ax", "ay"), ("ax", "az"), ("wx", "wy")]:
        agg[f"corr_{a}_{b}"] = X.groupby("id").apply(lambda g: g[a].corr(g[b]))

    return agg.fillna(0)                            # กลุ่มที่มีแถวเดียวจะได้ std เป็นค่าว่าง

def prune(df):
    df = df.loc[:, df.nunique() > 1]                # คอลัมน์ที่มีค่าเดียวไม่มีข้อมูลอะไรเลย
    keep, seen = [], df.corr().abs()
    for c in df.columns:                            # ตัดคอลัมน์ที่แทบซ้ำกันออก
        if not any(seen.loc[c, k] > 0.98 for k in keep):
            keep.append(c)
    return df[keep]
```

โค้ดนี้จงใจไม่ใส่การปรับสเกล เพราะโมเดลที่จะใช้ในวันที่ 2 คือ boosting ซึ่งไม่ต้องการการปรับสเกล ให้เพิ่ม `StandardScaler` เข้าไปทันทีที่เริ่มทดลองใช้ kNN หรือ logistic regression กับคุณลักษณะชุดนี้

## ข้อควรระวัง และสรุปสำหรับอ่านทบทวน 60 วินาที

- ตัวปรับสเกลและค่าสถิติทุกตัวต้องคำนวณจาก **ข้อมูลสอนเท่านั้น** แล้วจึงนำไปใช้กับข้อมูลทดสอบ ถ้าคำนวณจากทั้งสองฝั่งรวมกันจะเกิดข้อมูลรั่ว (data leakage)
- โมเดลกลุ่มต้นไม้ไม่สนใจสเกลของตัวเลข แต่โมเดลที่คำนวณระยะทางสนใจมาก
- เมื่อคำตอบเป็นเรื่องของ "ทำอย่างไร" ไม่ใช่ "ทำเท่าไร" คุณลักษณะที่วัดการกระจายจะสำคัญกว่าค่าเฉลี่ย
- เซ็นเซอร์หลายแกนควรสร้างคุณลักษณะขนาดรวมเสมอ เพราะมันกำจัดปัญหาเรื่องทิศทางการติดตั้งออกไป
- คอลัมน์ที่มีค่าเดียวและคอลัมน์ที่ซ้ำกันตัดทิ้งได้โดยไม่เสียอะไร ให้ทำก่อนเริ่มสร้างโมเดล
- ถ้ากรรมการให้รายการคุณลักษณะมาแล้ว อย่างในไฟล์ `qaz_letters.md` ให้ข้ามขั้นตอนนี้ไปเลย แล้วนำเวลาไปใช้กับการเลือกและปรับโมเดลแทน
