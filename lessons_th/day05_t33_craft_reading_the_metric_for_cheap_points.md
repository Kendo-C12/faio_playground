**เกณฑ์ให้คะแนน (metric)** คือ สูตรที่ผู้จัดใช้แปลงคำตอบที่ส่งไป ให้กลายเป็นตัวเลขคะแนน เกณฑ์นี้เป็นสิ่งเดียวที่ตัดสินผล ดังนั้นมันจึงบอกด้วยว่าความผิดพลาดแบบไหนแพง และความผิดพลาดแบบไหนไม่มีราคาเลย

หัวข้อนี้สำคัญเพราะการอ่านเกณฑ์ให้คะแนนอย่างละเอียดก่อนเริ่มสร้างโมเดล จะตัดสินใจแทนไปได้ประมาณครึ่งหนึ่งของการตัดสินใจทั้งหมดในรอบสอบ โดยไม่ต้องทดลองอะไรเลย

## [concept-first] ทฤษฎีก่อน แล้วดูตัวอย่าง

**เขียนเกณฑ์ให้คะแนนขึ้นมาใช้เองในเครื่องก่อนเป็นอันดับแรก** ก่อนจะสร้างโมเดลใด ๆ ให้เขียนฟังก์ชันคำนวณคะแนนตามสูตรในโจทย์สักห้าบรรทัด แล้วลองป้อนคำตอบที่เดาขึ้นมาเข้าไป

ผลที่ได้คือมีตัวเลขที่ขยับได้อยู่ในมือ และได้เรียนรู้นิสัยของเกณฑ์นั้นจากการลองป้อนค่าต่าง ๆ เข้าไปดู การตัดสินใจทุกข้อที่จะกล่าวถึงต่อจากนี้ ล้วนมาจากฟังก์ชันนั้น ไม่ได้มาจากความรู้สึก

**ถามว่าเกณฑ์นี้ไม่สนใจอะไรบ้าง** สิ่งที่เกณฑ์ไม่สนใจคือใบอนุญาตให้หยุดทำงานตรงนั้น เพราะงานที่ทำเพิ่มจะไม่ได้คะแนนเพิ่มเลย

- โจทย์ [`Lost_in_the_Museum.md`](../faio-2025/day2/Lost_in_the_Museum.md) ให้คะแนนด้วย Hit@3 โดยเขียนว่า "ถือว่าคำค้นหนึ่งคำตอบถูก ถ้าภาพต้นฉบับความละเอียดสูงที่คู่กันอยู่ปรากฏภายในสามอันดับแรกของผลลัพธ์" ความหมายคือ ลำดับภายในสามอันดับแรกนั้นเกณฑ์มองไม่เห็น และทุกอันดับที่ต่ำกว่าสามลงไปไร้ค่าเท่ากันหมด ดังนั้นการพยายามเพิ่มระยะห่างของคะแนนเป็นแรงที่สูญเปล่า และมีเฉพาะคำค้นที่อยู่ใกล้เส้นแบ่งเท่านั้นที่มีความหมาย

- โจทย์เดียวกันยังเขียนอีกว่า embedding "ควรผ่านการทำ L2-normalisation เพื่อประสิทธิภาพสูงสุด แม้ว่าคำตอบที่ไม่ได้ทำก็ยังรับได้" ความหมายคือ cosine ไม่สนใจขนาดของชุดตัวเลข ดังนั้นขนาดของเวกเตอร์คือข้อมูลที่เกณฑ์โยนทิ้งไปเฉย ๆ

- โจทย์ [`task6_Simple_Objects.md`](../faio-2025/qualification/task6_Simple_Objects.md) ขอเพียงจำนวนนับ โดยเขียนว่า "คุณเพียงต้อง **นับ** จำนวนรูปทรงเท่านั้น ไม่ต้องแยกประเภทของมัน" ความหมายคือ การแยกประเภทของรูปทรงเป็นงานที่ทำเพิ่มได้ แต่เกณฑ์ไม่จ่ายเงินให้

**ความคลาดเคลื่อนสัมพัทธ์ทำให้ภาพที่มีของน้อยมีน้ำหนักมากกว่า** เกณฑ์ของโจทย์ข้อ 6 คือ

$$
\text{Error Rate} = \frac{\lvert \hat{y} - y \rvert}{y}
$$

$$
\text{Accuracy} = 1 - \min(1, \text{Error Rate})
$$

เมื่อ $\hat{y}$ คือ จำนวนที่โมเดลทำนาย, $y$ คือ จำนวนที่ถูกต้องจริง, เครื่องหมาย $\lvert \cdot \rvert$ คือ ค่าสัมบูรณ์ซึ่งตัดเครื่องหมายลบทิ้ง และ $\min(1, \cdot)$ คือ การจำกัดค่าไม่ให้เกิน 1

จุดสำคัญอยู่ที่ตัวส่วน ซึ่งคือจำนวนที่ถูกต้องจริง และมีค่าอยู่ในช่วง $100 \le N \le 500$ ตามที่โจทย์กำหนด

ลองคิดเลขดู ถ้านับพลาดไป 10 ชิ้นที่ $y = 500$ จะเสียคะแนน 0.02 แต่ถ้านับพลาดไป 10 ชิ้นเท่ากันที่ $y = 100$ จะเสียคะแนน 0.10 ซึ่งแย่กว่าถึงห้าเท่า ทั้งที่ความผิดพลาดในเชิงจำนวนชิ้นเท่ากันทุกประการ

**ข้อสรุปคือ ต้องวัดผลกับภาพที่มีของน้อยเป็นหลัก** ชุดข้อมูลที่ใช้ปรับจูนควรเอนไปทางภาพที่มีค่า $y$ ต่ำ ไม่ใช่สุ่มมาแบบกระจายเท่ากัน เพราะคะแนนที่เสียไปกระจุกอยู่ตรงนั้น

การคิดเลขชุดเดียวกันยังบอกอีกเรื่องหนึ่งว่า ความผิดพลาดที่เอนไปทางเดียวกันเสมอ แย่กว่าความผิดพลาดที่แกว่งสุ่ม การนับเกินไป $+5$ ในทุกภาพ ทำให้เสียคะแนนในทุกภาพที่มีของน้อย ส่วนความผิดพลาดแบบสุ่ม $\pm 5$ จะหักล้างกันไปบางส่วนเมื่อเฉลี่ยจากภาพทั้ง 8000 ภาพ

**เมื่อมีเกณฑ์ขั้นต่ำ การทำแบบขอไปทีจะได้ศูนย์พอดี** โจทย์ข้อ 6 ปรับคะแนนอีกชั้นหนึ่งด้วยสูตร

$$
\text{Final Verdict} = \frac{\text{Accuracy} - 0.55}{1 - 0.55}
$$

เมื่อ 0.55 คือ เกณฑ์ขั้นต่ำที่ต้องผ่านก่อน และคะแนนที่ต่ำกว่าเกณฑ์นั้นถูกนับเป็น 0 ทั้งหมด

ผลที่ตามมาคือ คะแนน accuracy ที่ 0.54 กับคะแนน accuracy ที่ 0.01 มีค่าเท่ากันพอดี คือไม่ได้อะไรเลย ดังนั้นงานแรกสุดคือ *ทำให้ผ่านเกณฑ์ขั้นต่ำให้ได้ก่อน* ซึ่งต้องการความคลาดเคลื่อนสัมพัทธ์ต่ำกว่า 0.45 หรือพูดง่าย ๆ คือ นับให้ได้จำนวนที่คลาดจากความจริงไม่เกินประมาณ $\pm 45\%$

การนับเส้นขอบแบบธรรมดาผ่านเกณฑ์นี้ได้สบาย วิธีที่คนพลาดเกณฑ์นี้บ่อยที่สุดไม่ใช่ความไม่แม่นยำ แต่เป็นข้อผิดพลาดเชิงโครงสร้าง เช่น การใช้ `RETR_LIST` ซึ่งทำให้รูปทรงกลวงทุกชิ้นถูกนับซ้ำสองครั้ง ดังนั้นให้ตรวจว่าผ่านเกณฑ์ขั้นต่ำแล้วจริง ก่อนจะไปปรับจูนอะไรที่อยู่เหนือเกณฑ์นั้น

**Macro-F1 ทำให้ประเภทที่มีข้อมูลน้อยฉุดคะแนนได้** ไฟล์เฉลยอ้างอิงของโจทย์ข้อ 4 คือ [`task4_solution_Who_Speaks_What.ipynb`](../faio-2025/qualification/task4_solution_Who_Speaks_What.ipynb) ให้คะแนนด้วย `classification_report` และการค้นหาค่าพารามิเตอร์ในไฟล์นั้นก็ปรับจูนบน `scoring="f1_macro"` ไม่ใช่ accuracy

**Macro-F1** คือ การหาค่า F1 ของแต่ละประเภทแยกกัน แล้วเอามาเฉลี่ยโดย **ไม่ถ่วงน้ำหนักตามจำนวนข้อมูล** ผลคือประเภทที่มีข้อมูลเพียง 5% ของทั้งหมด แบกคะแนนไว้หนึ่งในสามเท่ากับประเภทที่มีข้อมูล 60%

ถ้าใช้เกณฑ์ accuracy ธรรมดา การละเลยประเภทเล็กนั้นแทบไม่เสียอะไร แต่ภายใต้ macro-F1 การที่โมเดลไม่เคยทำนายประเภทเล็กเลย ทำให้เสียคะแนนไปถึง 0.33

ข้อสรุปเชิงปฏิบัติมีสามข้อ ข้อแรกคือให้ดูค่า recall (สัดส่วนของข้อมูลจริงในประเภทนั้นที่โมเดลจับได้) แยกรายประเภท ไม่ใช่ดูตัวเลขรวม ข้อที่สองคือให้พิจารณาตั้งค่า `class_weight="balanced"` ข้อที่สามคือการเพิ่มข้อมูลให้ประเภทที่อ่อนแอ ซึ่งไฟล์เฉลยใช้เทคนิค `kazakh_to_russian` และ `translit` จะขยับ macro-F1 ได้มากกว่าขยับ accuracy อย่างเทียบกันไม่ได้

**เกณฑ์แบบจัดอันดับสนใจเฉพาะลำดับต้น ๆ เท่านั้น** โจทย์ HearMe จ่ายคะแนนตามผลรวม $\sum_j f_j$ ของสัดส่วนที่ผู้ใช้ฟังจริง จากช่องแนะนำเพลง 50 ช่องต่อผู้ใช้หนึ่งคน ตามที่ระบุใน [`HearMe_Personalized_Music_Recommender.md`](../faio-2025/day2/HearMe_Personalized_Music_Recommender.md) แล้วปรับให้อยู่ในช่วง 0 ถึง 1

สิ่งที่อยู่นอก 50 ช่องนั้นไม่ถูกนับคะแนนเลย อันดับที่ 51 เป็นต้นไปจึงไม่มีตัวตนในสายตาของเกณฑ์ และข้อความในโจทย์ที่ว่า "การฟังซ้ำไม่ได้คะแนนเพิ่ม" ก็จำกัดคะแนนของแต่ละช่องไว้ที่ 1

ผลที่ตามมาคือ ความถูกต้องของคะแนนที่โมเดลให้กับเพลงทั้งคลัง ไม่มีความสำคัญเลย มีเพียงคำถามเดียวที่สำคัญ คือเพลง 50 เพลงที่ติดอันดับต้นของผู้ใช้แต่ละคนนั้นคือเพลงอะไรบ้าง

**เรื่องหนึ่งที่ต้องพูดให้ชัด** เมื่อพบว่าโจทย์ในคลังข้อสอบพิมพ์ผิดอย่างเห็นได้ชัด สิ่งที่ถูกต้องคือแก้โจทย์ตามความหมายที่ผู้ออกข้อสอบตั้งใจ และแจ้งความกำกวมนั้นให้ผู้จัดทราบ

โจทย์ข้อ 6 พิมพ์สูตรไว้ว่า

$$
\text{Final Verdict} =
\begin{cases}
0, & \text{if Accuracy} > 0.55 \\
\dfrac{\text{Accuracy} - 0.55}{1 - 0.55}, & \text{otherwise}
\end{cases}
$$

ถ้าอ่านตามตัวอักษรทุกประการ สูตรนี้ให้ 0 คะแนนกับคำตอบที่ดีทุกคำตอบ และให้คะแนนกับคำตอบที่แย่แทน นั่นคือเงื่อนไขถูกสลับด้านโดยความผิดพลาดในการพิมพ์

ความหมายที่ผู้ออกข้อสอบตั้งใจนั้นชัดเจนอยู่ในตัว คือให้ 0 คะแนนเมื่อ accuracy อยู่ *ต่ำกว่า* 0.55 การตอบสนองที่ถูกต้องจึงมีสองอย่าง คือทำให้ accuracy สูงที่สุดตามความหมายที่ตั้งใจไว้ และถ้าการแข่งขันมีช่องทางสอบถามข้อสงสัย ก็ให้ถามไปตามช่องทางนั้น

การจงใจเขียนคำตอบที่แย่เพื่อใช้ประโยชน์จากข้อความที่พิมพ์ผิด ไม่ใช่กลยุทธ์ และไม่ใช่สิ่งที่บทเรียนนี้สอน เหตุผลในทางปฏิบัติก็ชัดเจนด้วย เพราะโปรแกรมตรวจคะแนนย่อมถูกเขียนตามความหมายที่ตั้งใจไว้ วิธีนั้นจึงล้มเหลวทันทีที่คำตอบถูกตรวจจริง ส่วนเหตุผลที่สำคัญกว่านั้นคือ งานของผู้เข้าสอบคือแก้โจทย์ที่ผู้ออกข้อสอบตั้งใจจะถาม

## [problem-first] เริ่มจากโจทย์จริง แล้วหาว่าต้องรู้อะไร

เปิดไฟล์ [`task6_Simple_Objects.md`](../faio-2025/qualification/task6_Simple_Objects.md) แล้วลองสร้างแผนการทำงานทั้งหมดจากหัวข้อการประเมินผลเพียงหัวข้อเดียว

1. เกณฑ์ให้คะแนนดูที่ **จำนวนนับ** ดังนั้นไม่ต้องสร้างโมเดลแยกประเภท การหาองค์ประกอบที่เชื่อมต่อกัน (connected components — กลุ่มของจุดภาพที่ติดกันเป็นชิ้นเดียว) ก็เพียงพอแล้ว และโจทย์ยังยื่นหลักประกันมาให้ด้วยว่า "รูปทรงแต่ละชิ้นเป็นองค์ประกอบที่เชื่อมต่อกันเพียงชิ้นเดียว เมื่อพิจารณาจากจุดภาพที่เป็นเส้นขอบ"

2. ความคลาดเคลื่อนคิด **เทียบกับค่า $y$** ดังนั้นให้สร้างชุดวัดผลที่เอนไปทางภาพที่มีค่า $y$ ใกล้ 100 โดยใช้จำนวนจริงที่อยู่ในไฟล์ `train.csv`

3. ความคลาดเคลื่อนคิดจาก **ผลต่างสัมบูรณ์** ไม่ใช่ผลต่างยกกำลังสอง ดังนั้นการพลาดมาก ๆ ไม่กี่ครั้ง เสียคะแนนเท่ากับการพลาดน้อย ๆ หลายครั้ง สิ่งที่ควรไล่แก้คือความเอนเอียงที่เป็นระบบ ไม่ใช่ความแกว่ง

4. มี **เกณฑ์ขั้นต่ำที่ 0.55** ดังนั้นเป้าหมายแรกคือคำตอบที่พิสูจน์ได้ว่าอยู่เหนือเกณฑ์นั้นเมื่อวัดกับข้อมูลฝึก ไม่ใช่คำตอบที่ดี

5. ตัว $\min(1, \cdot)$ **จำกัดการหักคะแนนไว้ที่ 1** ดังนั้นภาพหนึ่งภาพที่พังโดยสิ้นเชิงก็ทำให้คะแนนต่ำกว่า 0 ไม่ได้ ข้อสรุปคือเมื่ออ่านภาพไม่สำเร็จ ให้ตอบด้วยค่าคงที่ที่สมเหตุสมผล เช่น มัธยฐานของข้อมูลฝึก แทนที่จะปล่อยให้โปรแกรมหยุดทำงานทั้งชุด

6. มีภาพทั้งหมด **8000 ภาพ** ดังนั้นเวลาที่ใช้รันกลายเป็นส่วนหนึ่งของคะแนนโดยปริยาย เพราะงานที่รันไม่จบจะไม่ได้ไฟล์คำตอบออกมาเลย

สิ่งที่อ่านได้คือ เกณฑ์ให้คะแนนไม่เคยเห็นตัวโมเดลเลย ดังนั้นไม่มีคะแนนใดผูกกับสถาปัตยกรรมของโมเดล มีเพียงคำถามเดียวคือ ภาพคำค้นกับภาพต้นฉบับที่คู่กัน ออกมาอยู่ใกล้กันภายใต้ cosine หรือไม่ ข้อสรุปคือควรใช้เวลาทั้งรอบไปกับการทำให้ชุดตัวเลขทนต่อความต่างของสภาพภาพ เช่น ภาพเบลอ แสงสะท้อน และการตัดขอบ และไม่ควรใช้เวลากับส่วนหัวของโมเดลที่ทำหน้าที่แยกประเภทเลยแม้แต่น้อย

## [code-first] โค้ดที่รันได้ พร้อมคำอธิบายในคอมเมนต์

```python
import numpy as np, pandas as pd
from sklearn.metrics import f1_score, classification_report

# ---- ข้อ 6: เขียนเกณฑ์ให้คะแนนตามโจทย์ทุกตัวอักษร ก่อนจะสร้างโมเดลใด ๆ ----
def faio_accuracy(y_hat, y):
    err = np.abs(np.asarray(y_hat, float) - np.asarray(y, float)) / np.asarray(y, float)
    return 1.0 - np.minimum(1.0, err)

def final_verdict(y_hat, y, floor=0.55):
    acc = faio_accuracy(y_hat, y)                 # ความถูกต้องรายภาพ
    # ความหมายที่ตั้งใจไว้: ได้ 0 เมื่ออยู่ "ต่ำกว่า" เกณฑ์ขั้นต่ำ ตัวโจทย์พิมพ์เงื่อนไขสลับด้าน
    return np.where(acc < floor, 0.0, (acc - floor) / (1 - floor)).mean()

train = pd.read_csv("train.csv")                  # จำนวนจริงที่ถูกต้อง
# ความคลาดเคลื่อนสัมพัทธ์ทำให้ y ที่น้อยมีน้ำหนักมาก จึงต้องวัดคะแนนของกลุ่มที่มีของน้อยแยกต่างหาก
low = train[train.count_col <= 150]
print("all :", final_verdict(pred_all, train.count_col))
print("lowN:", final_verdict(pred_low, low.count_col))     # ตัวเลขที่มีความหมายจริง

# ตรวจความเอนเอียง: ความคลาดเคลื่อนเป็นระบบหรือไม่ ถ้าเป็นระบบก็แก้ได้และคุ้มที่จะแก้
resid = pred_all - train.count_col
print("median bias", np.median(resid), "| IQR", np.subtract(*np.percentile(resid,[75,25])))

# ---- ข้อ 4: ใช้ macro-F1 ไม่ใช่ accuracy ให้จับตาประเภทที่อ่อนแอที่สุด ----------
print(classification_report(y_true, y_pred, digits=3))      # ค่า recall รายประเภท
print("macro F1", f1_score(y_true, y_pred, average="macro"))
print("accuracy", (y_true == y_pred).mean())   # ตัวเลขนี้จะหลอกให้ใจฟู ให้ข้ามไป

# ---- Hit@3: เป็นตัวชี้วัดแบบใช่/ไม่ใช่ จึงมีแต่คำค้นใกล้เส้นแบ่งที่คุ้มจะลงแรง ------
def hit_at_3(Q, G, truth):                     # Q และ G ผ่านการทำ L2 มาแล้ว
    sims = G @ Q.T                             # (คลังภาพ, คำค้น)
    top3 = np.argsort(-sims, axis=0)[:3]
    return np.mean([truth[j] in top3[:, j] for j in range(Q.shape[0])])

# ที่ที่ควรลงแรง: คำค้นที่ภาพคู่ที่ถูกต้องอยู่อันดับ 4 ถึง 10 ในตอนนี้
```
